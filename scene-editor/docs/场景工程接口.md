
# 场景工程接口 · deltarune-scene/1

遭遇战的触发、结算和资源引用见 [场景与战斗接线](场景战斗接线.md)。跨遭遇的队伍、库存、试玩档和转场见 [队伍、试玩存档与入战演出](队伍存档与转场.md)。

按格子画房间、文字地图和自定义多格零件（`room.grid`、`gridParts`）见 [逐格编辑](逐格编辑.md)。

运行器、编辑器、保存接口和命令行共用 `studio/format.mjs` 校验。先复制 `examples/echo-workshop.scene.json`，改动后运行校验；错误给出 JSON 字段路径。工程是数据，不能执行 JavaScript、GML 或网络请求。

```json
{
  "format": "deltarune-scene/1",
  "title": "入口试验",
  "viewport": { "w": 480, "h": 300 },
  "start": { "room": "hall", "entry": "arrival" },
  "rooms": {
    "hall": {
      "w": 640, "h": 360, "style": "workshop",
      "entries": { "arrival": { "x": 100, "y": 210, "face": "up" } },
      "entities": [
        { "id": "greeter", "kind": "npc", "name": "门卫", "x": 90, "y": 170, "w": 20, "h": 22, "solid": true, "event": "talk" }
      ]
    }
  },
  "events": {
    "talk": [
      { "op": "say", "pages": [{ "speaker": "门卫", "text": "请从右边过。" }] }
    ]
  }
}
```

坐标为房间像素，X 向右、Y 向下。入口是玩家脚边的碰撞中心；物件的 X/Y 是矩形左上角，W/H 默认 20。实体 ID 在整个工程中唯一；`player` 保留给演出指令。房间 ID、入口 ID、事件 ID 可以使用中文或字母、数字、下划线、连字符。默认视口 640×480，房间较小时居中，较大时跟随玩家。初始 `flags` 和 `inventory` 可以省略。可选 `player` 指定 `sprite`、`color`、`speed`（像素/步）、`radius`、`reach`。`room.camera` 指定进入房间时镜头中心；不指定则跟随玩家。

| 物件 `kind` | 常用字段与含义 |
|---|---|
| `wall` / `block` | 墙是固体；推块可以被玩家推动并压住踏板。实体也可以显式设 `solid:true`。 |
| `npc` / `prop` | 面向物件按 Z；用 `event` 绑定事件、`sprite` 绑定图片或动画。 |
| `door` | `room` 和 `entry` 都填时连接指定入口；两项都留空时只摆放门。默认按 Z，`auto:true` 可改为接触触发。 |
| `zone` | 默认进入时触发，可设 `auto:false` 改为按键。抵达入口时不会立即触发重叠区。 |
| `switch` | `flag` 是输出；玩家或推块可压住，多个同名踏板取任一。默认离开即释放，`latch:true` 可保持。 |
| `mode` | `mode` 是 `walk`、`slide` 或 `climb`；攀爬区可设 `grip`，`rest:true` 作为恢复抓力的重叠区域。也可设 `room.mode`。 |
| `checkpoint` | 默认踩到记录本次试玩状态。X 恢复房间、位置、物品、旗标、道具位置等。 |
| `savepoint` | 可跨刷新读取的试玩档。默认 Z 确认并回满 HP；可设置 `heal`、`confirm` 和读档回到的 `entry`。 |
| `hold` | 面向后长按 Z；`ticks` 是进度上限，`decay` 是松手每步衰减（默认 2）。完成时执行事件。 |

通用字段：`when` 决定能否使用，失败执行 `otherwise`；`activeWhen` 决定是否参与绘制、碰撞及互动；`once:true` 限制成功一次；`hidden:true` 初始隐藏；`facing:false` 放宽面向要求。`room.onEnter` 在转场后运行。条件语法：`{"flag":"ready","is":true}`、`{"item":"铜钥匙","count":1}`、`{"all":[...]}`、`{"any":[...]}`、`{"not":{...}}`。不存在的旗标和物品按 false / 0 处理。

| 指令 `op` | 参数 |
|---|---|
| `say` | `pages` 是字符串或 `{speaker,text,portrait}` 数组，头像是素材 ID。 |
| `choose` | `question`，`options:[{text,actions:[...]}]`，方向键选择，Z 确认。 |
| `flag` / `item` | `{id,value}` / `{id,delta}`。物品数量减到 0 为止。 |
| `hp` | `{member,delta}` 或 `{member,full:true}`。成员是共享队伍 ID 或 `"party"`。 |
| `battle` | `{battle}`，使用 `battles` 里的引用 ID；结算后继续场景。 |
| `branch` / `call` | `{if,then,else}` / `{event}`。条件数组可嵌套，禁止循环 call。 |
| `wait` / `timer` | `{ticks}` / `{ticks,event,global?}`。wait 阻塞演出；timer 异步排队，默认离开房间取消。 |
| `show` / `sprite` | `{actor,value}` / `{actor,sprite}`。用实体 ID；sprite 和 move 可指定 player。 |
| `move` / `camera` | `{actor,x,y,ticks?,face?}` / `{x,y,ticks?}` 或 `{follow:true}`。演出补间绕过走路碰撞，用于安排镜头和动作。 |
| `goto` | `{room,entry,fade?}`。转场结束当前指令序列，目标房间用 onEnter 继续。 |
| `mode` / `checkpoint` / `restore` | `{mode,grip?}` / 记录 / 恢复。检查点是本次试玩内的快照，重新开始会清空。 |

节奏事件本身是一个对象：`{"type":"rhythm","title":"试音","lead":30,"window":4,"minHits":2,"beats":[{"at":0,"key":"left"},{"at":24,"key":"act"}],"onWin":"passed","onLose":"try_again"}`。所有时间是 30 Hz 逻辑步；`at` 从预备完成起计。输入为 `up/down/left/right/act`，每个拍点按一次。成功或失败后调用相应事件。

素材：`assets` 下填图片 URL 或 `{src, frames, ticks, anchor, idle_down, walk_left, ...}`。图片可以是已注册的本机官方/自制素材路径或内嵌 data URI。四向各支持 idle 和 walk；动画帧数组共用 `ticks`。`anchor` 可用 `feet`（默认）、`center` 或 `topLeft`。房间可有 `scenery` / `foreground` 图片、V0.4 `map`（保留图层及素材裁切）及 `frontLayers`（要画在人物前的图层 ID）。用 `official:{chapter,room}` 关联物件候选。动画条继承旧布景的帧、循环和播放状态。

命令行：

```powershell
node tools/scene.mjs validate examples/echo-workshop.scene.json
node tools/scene.mjs replay examples/echo-workshop.scene.json examples/echo-workshop.replay.json
node tools/verify-example.mjs
```

复放是一组 `{n,hold?,press?,mark?}`。`hold` 在连续 n 步保持，`press` 只用于该组第一步，`mark` 记录该组结束的状态。输入含 `cancel`（X）。命令行的测试不读取素材；发布前仍须在工作台或离线 HTML 检查实际画面和图片解析。
