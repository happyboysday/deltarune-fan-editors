# 横版地下城玩法规格（V0.7 契约）

本文件是三个并行开发会话的共同契约。字段名、取值和默认值以本文为准；实现中如发现本文矛盾或无法实现，先在汇报里说明，不要各自另起一套。

目标：在场景编辑器里**不写代码**就能做出类似 DELTARUNE 第 5 章横版视角的动作地下城：

- 主角（及以后的可操作角色）可设定待机、行走、奔跑、跳跃、下落、攻击连段、闪避、受伤、倒下、技能等动画与参数；
- 背景方块、实体方块、装饰方块、敌人全部用现有「逐格放置」方式摆放；
- 背景与装饰可设「高优先级」，能遮住主角和敌人，便于做伪 3D 美术（柱子、栏杆、前景植物挡住角色）；
- 人和其他 AI 模型都能轻松使用：所有内容是普通 JSON，有命令行文字地图，有校验与示例。

## 0. 兼容原则

- 继续使用 `deltarune-scene/1`，所有新字段都是可选的。旧工程（含 `docs/CH6-TRAILER-SCHEMA.md` 的宣传片地下城、赛车）行为不变，`tools/test-ch6-trailer-modes.mjs` 必须继续通过。
- 房间仍用 `room.mode = "dungeon"`，物理沿用 `room.platform`（重力、跳跃、单向平台等）。没有配置 `fighter` 时，主角就是宣传片里的内置 Kris（现有斩击/剑气/弹反），等同于今天的行为。
- 坐标单位是房间逻辑像素；时间：动画用 tick（30 Hz），冷却与间隔用秒（与宣传片文档一致）。

## 0.5 素材：只用官方第 5 章横版素材

宣传片工程（`ch6-trailer-project`）的地下城素材和程序化 Kris 质量不达标，**测试、示例、预设一律使用官方第 5 章横版素材**：

- 本机官方库：`DeltaruneWorks/assets-official/01-official/`（只读）。
  - `animations/Kris/<动作>/spr_kris_plat_*/frame_NNN.png` + `meta.json`：第 5 章横版 Kris 全帧动画——`spr_kris_plat_idle`、`_run`、`_runstop`、`_turn`、`_land`、`_crouch`、`_hurt_ground`、`_hurt_air`、`_slash_ground`（及 `_slash_ground_foreground` 前景层）、`_slash_air`（及 `_foreground`）、`_slash_airland`、`_clash`、`_climb`、`_pose`；`spr_kris_plat_slash_hbx` / `_slash_hbxair` 是官方斩击判定框精灵，用来推算攻击 `hitbox`。
  - `maps/ch5/tilesets/*.png` + `maps/ch5/tilesets_meta.json`：瓦片集（暗世界 40×40，2 px 边界）；`maps/ch5/rooms/rooms_instances.json` 可查第 5 章横版房间用到的瓦片集与物件，例如 `room_dw_cliff_dash_runner`、`room_dw_cliff_twirlflowerplatforming`、`room_dogplatforming`、`room_dw_fcastle_dangerous_platforming`；`rooms/rendered/` 有官方渲染图可对照。
  - `sprites/ch5/all_sprites/`（每个只有第 0 帧）、`enemy-animations/`（敌人全帧）。
- 帧的原点（origin）不在 `meta.json` 里；需要时用 UTMT（`DeltaruneWorks/tools-external/utmt/UndertaleModCli.exe`，读 `DeltaruneWorks/game/DELTARUNE/chapter5_windows/data.win`）导出 `OriginX/OriginY` 等元数据，产物放在被 git 忽略的 `.research/`，结论写进预设。
- 手感与时序尽量贴近第 5 章横版战斗：可用 UTMT 反编译第 5 章横版相关对象（Kris 横版控制、斩击、敌人）的 GML 作为依据。

## 1. 动画（anim）

任何「动画」字段的值是：

- 字符串：`project.assets` 里的素材 ID；素材可以是单图、`{src}`、或 `{frames:[...], ticks, anchor}`；
- 或内联对象：`{"frames": ["url", ...], "ticks": 4, "loop": true, "anchor": "feet", "offset": [0, 0], "flip": false}`。

约定：
- **缩放 `scale`**（V0.7 追加）：动画对象与 `project.assets` 素材条目都可写 `"scale": 2`（缺省 1，允许 0.25–8）。DELTARUNE 暗世界的角色与敌人精灵以 2 倍绘制在 40 px 网格房间里（瓦片集本身已是 40 px，不放大），官方横版 Kris、敌人预设一律 `scale: 2`。`anchor`、`offset` 按原生像素写，随 `scale` 放大；`hitbox`、`box`、速度、射程等**一律按房间像素**（即已放大后的尺寸）。
- 横版角色/敌人的美术**默认面朝右**，朝左时运行时水平镜像。若素材本身面朝左，设 `"flip": true`。
- `anchor` 缺省为 `feet`（脚底中点对齐角色位置）。`offset` 是锚点再偏移的像素（面朝右时的方向，朝左自动镜像）。
- `loop` 缺省：待机/行走/奔跑/下落为 true，其余为 false（播完停在最后一帧）。
- 动作的持续时间由动作参数决定（见下），动画按自身 `ticks` 播放；若动作比动画长，非循环动画停在末帧。

## 2. 可操作角色 `project.fighters`

```json
"fighters": {
  "kris": {
    "name": "Kris",
    "hp": 120,
    "box": {"w": 18, "h": 34},
    "walkSpeed": 3.2, "runSpeed": 5.4, "jump": 10.7,
    "anims": {
      "idle": "kris_side_idle", "walk": "kris_side_walk", "run": "kris_side_run",
      "jump": "kris_side_jump", "fall": "kris_side_fall",
      "hurt": "kris_side_hurt", "down": "kris_side_down", "dodge": "kris_side_dodge"
    },
    "attacks": [
      {"anim": "kris_slash1", "windup": 2, "active": 3, "recovery": 6,
       "hitbox": {"x": 6, "y": -30, "w": 28, "h": 22}, "damage": 2, "lunge": 3, "knockback": 3,
       "hitstop": 3, "effect": "slash_arc_1"}
    ],
    "airAttack": {"anim": "kris_air_slash", "windup": 1, "active": 4, "recovery": 5,
       "hitbox": {"x": 0, "y": -36, "w": 30, "h": 30}, "damage": 2},
    "comboWindow": 15,
    "dodge": {"anim": "kris_dodge", "ticks": 9, "speed": 9.2, "invulnerable": 9, "cooldown": 0.35, "afterimages": true},
    "skills": [
      {"id": "wave", "name": "剑气", "input": "skill1", "type": "projectile", "anim": "kris_cast",
       "cooldown": 1.2, "cast": 4, "sprite": "crescent_wave",
       "projectile": {"speed": 7, "life": 40, "w": 26, "h": 30, "damage": 3, "pierce": true}}
    ]
  }
}
```

- 使用哪个角色：`room.dungeonConfig.fighter` 优先，其次 `project.player.fighter`；都没有就是内置 Kris。
- `box` 是碰撞框（脚底中点为原点，向上 `h`）。缺省沿用玩家 `radius`。
- **状态机**：`idle / walk / run / jump / fall / attack / airAttack / dodge / skill / hurt / down`。缺少某个动画时回退顺序：`run→walk→idle`，`fall→jump→idle`，`airAttack→attacks[0]`，`dodge→run`，`skill→attacks[0]→idle`，`hurt→idle`，`down→hurt`。缺少全部动画时沿用现有程序化 Kris 画法。
- **攻击**：`attacks` 是地面连段，按顺序循环，`comboWindow` 内再按攻击键接下一段（可提前缓冲一次）。帧阶段：`windup`（前摇）→ `active`（判定）→ `recovery`（后摇）。`hitbox` 是面朝右时相对脚底中点的矩形，朝左镜像。`lunge` 是起手时向前的位移速度，`hitstop` 是命中顿帧（只停动作物理），`knockback` 推开敌人。`effect` 是可选的斩击特效动画。`airAttack` 在空中按攻击键使用。
- **闪避**：`ticks` 期间以 `speed` 朝面向（或按下的方向）冲刺，`invulnerable` 是无敌 tick 数，`afterimages` 开启残影。
- **奔跑**：按住奔跑键时用 `runSpeed` 和 `run` 动画，否则 `walkSpeed` 和 `walk`。
- **受伤/倒下**：受击进入 `hurt`（短暂硬直与击退、无敌闪烁），HP 归零进入 `down`，然后按现有逻辑在 `retryEntry` 重开本房间遭遇。

### 技能 `skills[]`

公共字段：`id`、`name`、`input`（`skill1`–`skill4`）、`type`、`anim`、`cooldown`（秒）、`cast`（出招前摇 tick，期间不能移动）、可选 `sprite`（特效动画）、`sound`（可选 UI 音效名，可忽略）。

| type | 专属字段 | 行为 |
| --- | --- | --- |
| `projectile` | `projectile: {speed, life, w, h, damage, pierce?, gravity?, count?, spread?}` | 从角色前方发射，`count`>1 时按 `spread` 角度扇形 |
| `area` | `area: {x, y, w, h, damage, ticks, knockback?}` | 角色周围（面朝右相对脚底）的持续判定区，冲击波/旋风 |
| `parry` | `parry: {radius, window, reflect?, stun?}` | 现有弹反：窗口内反弹子弹、眩晕近敌 |
| `dash` | `dash: {speed, ticks, damage, invulnerable?}` | 带伤害的突进 |
| `heal` | `heal: {amount}` | 回复 HP |

内置 Kris 的剑气 = `projectile`，弹反 = `parry`，用于兼容。

## 3. 输入

逻辑输入在现有 `up/down/left/right/act/cancel/tool/dash/skill2` 基础上新增 `run`、`skill1`、`skill3`、`skill4`（`skill1` 与旧的 `tool` 等价，`skill2` 保持不变）。地下城房间默认按键：

| 按键 | 逻辑输入 | 地下城房间里的作用 |
| --- | --- | --- |
| ← → | left / right | 移动 |
| ↑ | up | 跳跃（沿用 platform） |
| Z | act | 攻击；有可互动对象时优先互动 |
| 按住 X | run | 奔跑（地下城房间里 X 不再是「回检查点」；回检查点用 Esc） |
| Shift / V | dash | 闪避 |
| C | skill1 | 技能 1（地下城房间里 C 不打开菜单，与持有工具的房间同理） |
| F | skill2 | 技能 2 |
| Q / E | skill3 / skill4 | 技能 3、4 |

时间线 / 导航脚本里写逻辑输入名。宣传片旧脚本里的 `tool`、`skill2` 照常生效。

## 4. 敌人 `project.enemyTypes` 与放置

```json
"enemyTypes": {
  "bloxer": {
    "sym": "G", "label": "积木兵", "cells": [1, 2], "color": "#ef7f93",
    "hp": 8, "damage": 10, "contact": true,
    "box": {"w": 20, "h": 30},
    "ai": "patrol", "speed": 0.9, "aggroRange": 160, "gravity": true,
    "anims": {"idle": "bloxer_idle", "move": "bloxer_walk", "attack": "bloxer_attack", "hurt": "bloxer_hurt", "die": "bloxer_die"},
    "melee": {"range": 28, "windup": 12, "active": 4, "recovery": 18, "hitbox": {"x": 4, "y": -26, "w": 24, "h": 20}, "damage": 14},
    "shoot": {"interval": 1.6, "delay": 0.6, "speed": 3.4, "count": 1, "spread": 0, "range": 220, "sprite": "bloxer_bullet", "color": "#ff72a7"},
    "onDefeat": "evt_bloxer_down"
  }
}
```

- `ai`：`patrol`（在两端或碰墙/悬崖处折返）、`chase`（进入 `aggroRange` 后追击，`gravity:true` 时会在地面行走）、`turret`（原地不动，只射击）、`flyer`（无重力，正弦漂浮并靠近玩家）。
- `melee` 与 `shoot` 都可选；都没有时只有接触伤害。死亡播 `die` 后消失并执行 `onDefeat`。
- **放置**：房间实体 `{"id": "g1", "kind": "actionEnemy", "enemyType": "bloxer", "x": 240, "y": 160, "w": 20, "h": 40}`。实体上的同名字段（`hp`、`damage`、`patrol`、`speed`…）覆盖类型默认值；宣传片里不带 `enemyType` 的旧 `actionEnemy` 照常工作。
- 每个敌人类型自动成为逐格调色盘里的一个零件，符号用 `sym`（大写字母，不得与内置和 `gridParts` 冲突），占格 `cells`。

## 5. 方块与图层 `project.tileParts`

```json
"tileParts": {
  "brick":  {"sym": "b", "label": "砖墙", "sprite": "tile_brick", "cells": [1, 1], "layer": "back"},
  "stone":  {"sym": "s", "label": "石地", "sprite": "tile_stone", "cells": [1, 1], "layer": "actor", "solid": "solid"},
  "ledge":  {"sym": "l", "label": "木台", "sprite": "tile_ledge", "cells": [2, 1], "layer": "actor", "solid": "oneway"},
  "pillar": {"sym": "p", "label": "前景柱", "sprite": "pillar_front", "cells": [1, 4], "layer": "front"},
  "vine":   {"sym": "v", "label": "藤蔓", "sprite": "vine", "cells": [1, 2], "layer": "actor", "depth": 4}
}
```

- `sym`：一个**小写**字母或数字（与地形/物件的大写符号分开）。`cells` 是占格（宽, 高）。`sprite` 是素材 ID（可以是多帧动画）；没有图时用 `color` 色块。
- `solid`：`none`（缺省，纯装饰）、`solid`（实体方块）、`oneway`（单向平台）。实体/单向方块在运行时就是墙，等同 `kind:"wall"` / `oneWay:true`，导航与 AI 跑图同样把它们当碰撞。
- `layer` 与优先级（伪 3D 的关键）：

| layer | 画在哪里 |
| --- | --- |
| `back` | 背景层，永远在角色和敌人后面（远景墙、窗） |
| `actor` | 与角色同层，按**底边 y**（`y + h + depth`）与角色、敌人、物件一起排序：角色脚底在方块底边上方时被挡住，走到前面时盖住方块 |
| `front` | 高优先级，永远盖在角色、敌人和特效上面（前景柱、栏杆、前景树叶） |

- `depth`（可选，像素，默认 0）加到排序用的底边上，用来微调「多靠前算挡住」。
- 房间里摆好的方块写在 `room.tiles`：`{"part": "pillar", "x": 320, "y": 160, "w": 20, "h": 80}`，可额外写 `layer`、`depth`、`activeWhen` 覆盖零件默认值。旧的 `{sprite, x, y, w, h, front}` 继续有效：`front:true` 等同 `layer:"front"`，否则等同 `back`。
- 同一格允许 back、actor、front 三层各放一个方块，以及一个地形（碰撞）和物件/敌人。

## 6. 视角与镜头

- 横版视角沿用第 5 章 `platform` 模式：画布 640×480（或项目 `viewport`），镜头水平跟随主角，房间高于视窗时垂直跟随；`room.camera` 照旧可锁定。
- 视差背景沿用 `room.parallax` 等宣传片字段。
- 状态栏：`room.dungeonConfig.hud` 为 `"top"`（默认，画布顶部紧凑栏，不遮挡战斗区）、`"bottom"` 或 `false`（隐藏）。
- 画面层次（从后到前）：视差/天空 → `scenery` 与地图后景 → `back` 方块 → `actor` 层（方块、角色、敌人、物件按底边排序）→ 斩击/技能/子弹特效 → `front` 方块 → 前景图/黑暗 → HUD 与对话。

## 7. 编辑器

- 房间设为地下城模式后，逐格面板出现**图层选择**：`碰撞`（墙、单向平台）、`背景`、`同层`、`前景`、`敌人与物件`。画笔、橡皮、矩形只作用于当前图层；其他图层半透明显示，可开关「只看当前层」。
- 调色盘按图层显示可用零件：图层零件显示素材缩略图；敌人页显示 `enemyTypes`。
- **新建方块零件**：选素材（或导入图片）→ 自动按格子尺寸算占格 → 设图层、碰撞、深度 → 写进 `tileParts`，自动分配空闲字母。
- **角色动作面板**：选择/新建 fighter；每个状态一个槽位（待机、行走、奔跑、跳跃、下落、攻击 1..n、空中攻击、闪避、受伤、倒下、各技能），可从素材库选择或导入帧序列，**实时预览动画**（可切换朝向、调 ticks），攻击可在预览上拖出判定框；技能用表单编辑类型参数。
- **敌人类型面板**：同样的动画槽位 + AI、血量、伤害、近战/射击参数，保存后进入敌人调色盘。
- 编辑器整体外观沿用现有工作台风格（这次允许改编辑器界面，但不要改网页试玩的原作风格 UI）。

## 8. 命令行（给 AI 用）

`tools/scene.mjs`：

- `grid show <工程> <房间> [--layer collision|back|actor|front|objects]`：打印该层文字地图；不带 `--layer` 时打印碰撞+物件（现有行为）。
- `grid apply <工程> <房间> <文字地图文件> [--layer ...]`：按该层写回。
- `parts <工程>`：列出内置零件、`gridParts`、`tileParts`、`enemyTypes` 的符号表。
- `dungeon init <工程> <房间> [--cols N --rows N --size 20]`：把房间设为地下城模式并生成带地面和左右墙的空白房间。

图层文字地图中 `.` 表示空，多格零件只在左上角写符号，其余被占格写零件符号的小写/同符号（与现有 `docs/逐格编辑.md` 的约定一致）。
