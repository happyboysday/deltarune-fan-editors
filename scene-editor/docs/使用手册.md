# 场景编辑器 V1.0 使用手册

## 安装与首次启动

1. 将发布 ZIP 解压到普通可写目录。安装 Python 3.11 或更新版本和 Pillow，并让 Windows 能运行 `py -3`。用 `py -3 -m pip install Pillow` 为该解释器安装 Pillow。也可以把环境变量 `PYTHON` 设为已有解释器的完整路径。
2. 安装 Node.js 并将其加入 PATH，以便使用工程保存、战斗打包和插件安装。双击 [launch-v1.cmd](../launch-v1.cmd)，浏览器会打开本机的 `http://127.0.0.1:18946/`。
3. 在首次启动引导中点「自动检测」，核对找到的目录，也可以手工填写。用「保存并重启」应用路径。暂时没有素材时，保留默认设置并完成引导，在首页打开「回声工坊」或新建空白工程。

关掉启动脚本的命令行窗口即停止服务。原章节快捷方式仍可使用 [launch-chapters.cmd](../launch-chapters.cmd)，它直接打开章节主线页，默认端口为 18947。

## 设置与素材目录

在首页打开「设置」，查看每项的当前值、来源、下次启动值和能力报告。命令行优先于设置文件，设置文件优先于默认值。用命令行指定的项可在启动参数中改动。清空设置项会恢复默认路径。可按需要配置下表中的目录。

| 设置 | 启动参数 | 目录内容 |
| --- | --- | --- |
| 场景素材 | `--assets` | `chapters/`、`chapter5/`、`official/` 物件候选、`ui-sprites/`、`art/chapter5/`、`art/dungeon-ch5/` |
| 官方素材 | `--official-root` | 解包的素材库，含 `sprites/chN/all_sprites` 等 |
| A-export | `--a-export` | 含房间索引的 v8 导出，有布景工作台时默认读取其 v8 目录，否则取场景素材下的 `a-export/` |
| 战斗素材 | `--battle-assets` | `index.json`、`sprites/`、`sprites-full/`、`audio/`、`fonts/`。也可用 `DR_ASSETS` 指定默认值 |
| 战斗编辑器 | `--battle-root` | 兼容场景联动的独立战斗编辑器，含 `serve.py`、`engine/`、`tools/export-game.mjs` |
| V0.4 布景工作台 | `--base` | 可选的原 V0.4 目录，用于打开布景工作台和交接旧布景 |
| 第 6 章制作素材 | `--ch6-assets` | 宣传片之外的第 6 章制作素材 |
| 宣传片工程 | `--trailer-root` | `assets/` 和 `scenes/` |
| 工程、插件 | `--projects`、`--plugins` | 可写的场景工程和用户插件目录，默认在数据目录下 |

用 `--data` 指定可写数据目录。省略时，它取命令行指定的工程目录的上一级，或程序目录旁的 `scene-studio-data/`。这里存放 `settings.json`、上传素材 `user-assets/`、动画序列 `user-assets/animations/`、章节试玩副本和默认战斗工作区。设置文件中的相对路径从数据目录解析。素材库与作者上传分别存放，旧版自定义素材可以继续从原登记中读取。

灰置入口的提示和能力报告会列出缺项。只有字体时仍可编辑和运行不依赖外部素材的工程，缺失图片会显示占位。要导入完整官方房间，在设置中同时检查 A-export 和官方素材。裸 v8 支持地图导入，完整原点、可见性和摆放校正的数据布局见 [开发者文档](开发者文档.md#外部数据与兼容).

## 场景编辑

1. 点「新建」或「导入工程 / 布景」。从本机工程目录继续工作时，用「打开存档」。具备素材时可以先打开顶部的「第 5 章地图」，按名称或 ID 筛选房间。
2. 添加房间并设置尺寸、入口和起始位置。用图层列表检查可见性和前后顺序。外部地图布景按房间加载，需要修改原始图层时先点「内嵌布景」。还可以在「官方房间」导入选中布景，在「物件候选」中核对并添加参考物件。
3. 用检查器设置门的目标房间和入口，添加 NPC、触发区、机关或道具。在「事件与演出」新建对白、分支或演出，再将事件 ID 绑定到对应物件。用「工程 JSON」读取、应用和校验精确修改。
4. 保存到本机工程目录，或导出 JSON 作为可继续编辑的副本。引用外部布景的工程需要相应图层和素材目录，分享可直接玩的版本时使用离线 HTML。

## 逐格编辑

设置房间的「每格」像素数，在零件盘选择地面、墙、门或其他物件。左键放置，右键擦除，中键拖动画面。画笔适合连续涂抹，矩形工具适合铺面，移动工具可调整已有物件。选中物件可在检查器更改属性和占格。想用大图制作长椅、柜台等零件时，点「＋ 自定义零件」，选图、设占格、字符和是否可穿过。用「文字地图」批量编辑时，每个字符代表一格，先读取当前房间，再将改好的文本应用到该房间。 [逐格编辑细节和快捷键](逐格编辑.md)

## 地下城和赛车

- **横版地下城**。从首页打开「横版地下城」，或在房间设置选择对应的内置模式。背景、同层、前景、碰撞和物件可以在同一格叠放。先铺地面和单向平台，再加入口、敌人、门和检查点。完整角色配置在 `fighters` 中，可通过 `player.fighter` 或房间的 `dungeonConfig.fighter` 选择。示例用左右移动、↑ 跳、按住 X 奔跑、Z 攻击或互动、Shift/V 闪避、C/F/Q/E 使用技能、Esc 返回检查点。宣传片旧版地下城配置支持月牙波和灵魂弹反，按画面下方的操作提示试玩。 [地下城作者手册](地下城玩法.md)
- **伪 3D 赛车**。选择伪 3D 赛车房间模式，在工程 JSON 的 `room.kartConfig` 配置赛道、对手、道具、素材和完成事件。已有宣传片赛车工程可直接打开修改。↑ 油门，↓ 刹车，←/→ 转向，Shift/V 漂移，Z/C 使用道具。 [赛车字段与演练输入](CH6-TRAILER-SCHEMA.md#伪-3d-赛车)

## 战斗接线

配置战斗编辑器和战斗素材后，可从首页打开「纸门值班室」。向上找值班员对话，或向右接触折纸哨兵，体验不同的开战入口。

1. 在「遭遇战与结算」选遭遇，来源可为默认工作区、战斗编辑器样例或作品库。在「编辑遭遇」打开原战斗编辑器，编辑并保存后回场景刷新。
2. 在事件中加入开战动作，或把遭遇绑到敌人接触。为胜利、饶恕、落败和逃离配置返回事件。
3. 运行战斗校验，核对遭遇、攻击、引用素材和结算事件。战斗期间场景暂停，结算后在原房间继续。离线导出会打包所用的战斗资源。 [战斗接线字段与路径](场景战斗接线.md)

## 队伍、试玩档与转场

用「余火接力」试验两场战斗间继承 HP 和道具。在「队伍与试玩档」启用共享队伍，填写角色 ID、当前和最大 HP、初始道具。对每场遭遇选择继承或单场独立。两边 ID 不同时，工程 JSON 中的 `partyMap`、`itemMap` 由遭遇 ID 映射到场景 ID。可为不同结算设置奖励。

在画布放置存档点，设置是否确认、是否回血、读档落点和保存后事件。配置落败时提示读档，试玩可从存档点复原。入战演出可选经典冲入、淡入和直接切换，单场遭遇可覆盖默认参数。试玩档和工程分开，试玩工具栏提供读取、导出及导入试玩档。建议不同作品使用各自的 `saveKey`。 [队伍和存档字段](队伍存档与转场.md)

## 章节主线

在首页进入「章节主线」，选第 4 或 5 章。章节的 `index.json`、`scripts.zip` 和 `edits.json` 可用于查看房间、定位剧情节点、保存位置和脚本。点击「生成试玩」重建还需要章节的 `chapter.json`、`resources.zip`、`dependencies.json`、本机正版游戏和 UndertaleModCli。可通过 `DIRECTOR_GAME` 和 `DIRECTOR_UTMT` 分别指定游戏和编译器。

「工作台内试玩」从标题和存档选择进入，可直接使用与当前编辑匹配的试玩副本。「从本段预演」使用独立存档，需要章节提供预演起点。即使有现成的试玩副本，段落预演也需要 UndertaleModCli 生成该段副本。试玩后可以导出按键与路线。完整章节运行的是 Windows 本机游戏，网页离线 HTML 适用于轻量场景工程。 [章节工作台操作与工程文件](章节主线工作台.md)

## 自动跑图

浏览器场景点「试玩」或「试当前房间」，章节主线点「工作台内试玩」。在画面下方展开「AI 自动跑图」，选择目的房间或探索未到过的房间，点「开始跑图」。章节还支持依次前往主线节点、自动翻普通对白和选择第一项。默认在有选项时等待人工处理。用「暂停 / 接管」或方向键接手。浏览器场景的寻路面板随编辑器提供，离线 HTML 仍可重放工程自带的宣传片时间线。 [自动跑图选项](自动跑图.md)

## 宣传片模式

配置宣传片工程目录后，可用 `?project=/ch6-trailer-scenes/工程名.scene.json` 从首页打开切片。用 `?project=…&autoplay=1` 直接演练，或者在编辑器试玩的跑图面板选择「宣传片时间线」。用工程 JSON 写入 `navScript` 及模式自己的脚本，安排移动、踩油门、剧情指令、镜头震动、闪白、淡入淡出与标题卡。需要录制器逐帧推进时在 URL 加 `manual=1`。 [宣传片字段、输入与录制接口](CH6-TRAILER-SCHEMA.md)

## 试玩与离线导出

普通场景用方向键或 WASD 移动，Z 调查、对话或用门，X 回到最近检查点，Shift＋Esc 回编辑。接触式门会在走到时触发。有水壶时可按住 C 使用。测试特定位置时选房间或入口再点「试当前房间」，这次预览的试玩档只在本次预览有效。

先用「校验工程」检查错误并试玩，再点「离线 HTML」。在浏览器直接打开下载的 HTML，检查离线素材、事件、战斗、读档和插件行为。HTML 会包含该工程使用的插件和可打包资源。保留工程 JSON 和外部素材用于后续修改。整章轻量地图、大量图片或战斗资源会让打包耗时和成品体积增加。

## 插件安装与管理

打开「插件管理」，输入含 `plugin.json` 的文件夹绝对路径，或选择最大 20 MiB 的 ZIP。ZIP 支持直接放插件文件或套一层目录。只安装信任来源的插件，插件代码会在浏览器和本机 Node.js 中运行。

安装发布包内的 `examples/plugins/fireflies` 后，用当前编辑器的地址和端口打开 `/?project=/plugins/fireflies/demo.scene.json`，即可进入「萤火小径」。点击「试玩」，向右收集三只萤火。内置地下城与赛车一直启用。用户插件可启用、停用或卸载，卸载后的目录保存在用户插件目录内的 `.plugins-trash/`，与插件处在同一卷。插件目录中的普通文件夹仅显示诊断信息。同 ID 已存在时，先确认现有插件及其工程依赖。停用或卸载导致打开的工程缺少依赖时，可先导出当前工程 JSON，补齐插件后重新打开。 [插件开发](插件开发.md)

## 常见问题与排错

| 现象 | 处理 |
| --- | --- |
| 双击立即关闭或找不到 Python | 在终端运行 `py -3 --version`。用 `PYTHON` 指定已安装的解释器，检查该解释器装有 Pillow |
| 浏览器打不开首页 | 查看启动窗口打印的本机 URL。端口被占用时可用 `launch-v1.cmd --port 18948` |
| 设置保存后仍是旧路径 | 查看「下次启动」与来源。用启动脚本点「保存并重启」，直接运行 Python 时手动重启 |
| 设置文件损坏 | 参考设置页的备份路径。每次成功保存也会保留一份 `settings.json.bak` |
| 官方房间、章节或素材入口变灰 | 按能力报告补齐对应目录或工具。检查是否误选了素材根目录的上一级 |
| 无法安装插件、保存工程或打包战斗 | 确认 Node.js 可用，检查插件或工程目录权限，再按页面诊断核对清单、依赖和战斗编辑器版本 |
| 离线 HTML 中出现占位图或存档未恢复 | 重新检查和导出素材，打开同一 HTML 后点「读取存档」。可用导出的试玩档 JSON 在不同位置或浏览器迁移 |
