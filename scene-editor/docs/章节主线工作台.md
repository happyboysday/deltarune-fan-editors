# 第 5 章与第 4 章的主线工作台

双击 [launch-chapters.cmd](../launch-chapters.cmd)，选择章节，再点「工作台内试玩」。普通试玩从本章的标题和存档选择进入。空档可以命名并开始首通。点击画面后用方向键移动，Z 确认、X 取消、C 打开菜单。Windows 上的 GameMaker 运行画面直接显示在工作台内，游戏音频由本机实例播放。

试玩后点「导出本次按键与路线」可保存本次启动以来的房间、剧情值、工作台按键变化与基础工程指纹。普通试玩与段落预演分别标记，上一场轨迹不会混入。此记录不包含在独立游戏窗口直接按下的键；做连续通关验收时，请在工作台画布内操作，结束后、下次启动前导出。

试玩画面下方的 **[AI 自动跑图](自动跑图.md)** 可代替人工走路，支持目的地、探索、按顺序去主线节点，以及暂停和接管。

## 从地图找到门禁

右侧节点可以定位到具体房间和控制器。例如，第 5 章的「早餐与烤面包机」指向 Toriel 家中的 LW02。事件列表优先显示该控制器的 Step 和 Create。打开「定位条件、换房或演出指令」，可以直接跳到剧情值、旗标、触发器、说话人或换房调用。选择房间中的具体物件，则能看到它的实例初始化、房间创建脚本及继承的物件事件。可在搜索框中输入任意控制器名，查找运行时才生成的人物和演出。

学校门前和雨夜庭院可以直接检验剧情门禁。

- 第 5 章学校门前。创建脚本先读取旗标 1324，处于夜间阶段时再用剧情值 590 区分告别演出和通关后的学校门。结尾预演从剧情值 570 开始，按键推进告别后进入片尾，剧情值变为 580。
- 第 4 章雨夜庭院。LWF04A 的创建条件是剧情值大于等于 310 且小于 320。演出完成后写入 320 并进入片尾。工作台可以从 310 单独预演这段。

编辑坐标后点「保存位置」。编辑 GML 后点「保存脚本」，再点「生成试玩」或「工作台内试玩」。编译失败会显示诊断，可用「恢复原文到编辑区」取回原脚本。点击保存后恢复才会生效。编辑器以房间内的摆放顺序区分个别重复的 GameMaker 实例编号。

「从本段预演」目前提供第 5 章悬崖冲刺、学校门前和第 4 章管风琴、旋转塔、雨夜庭院。预演使用单独的存档目录，界面中的章节试玩始终提供正常的新档入口。「读取最近轨迹」列出本次模式进入的房间和对应剧情值。退出章节或在末尾请求切章时，试玩返回工作台。

## 工程文件

| 文件 | 用途 |
|---|---|
| `chapters/ch5`、`chapters/ch4` | 两个独立工程。复制一整份即可保留当前作品及可运行副本。 |
| `chapter.json`、`resources.zip` | 房间、代码、动画、着色器等 GameMaker 资源块及其原始次序。 |
| `index.json`、`scripts.zip` | 房间、摆放、对象继承、事件绑定和完整的可搜索 GML。 |
| `edits.json` | 作者保存的改动。实例键是房间 ID 加斜线与从零开始的摆放顺序，脚本键是完整事件名。 |
| `previews.json` | 段落预演的房间、剧情值、入口、队伍和旗标。正式试玩不读取这些起点。 |
| `play`、`dependencies.json` | 可运行的章节副本，以及重建时采用的外部资源和运行程序版本。 |
| `build.json`、`verification.json` | 生成清单、独立参照校验和实际改动回读结果。 |

AI 可先在 `index.json` 找房间和事件，在 `scripts.zip` 定位原文，再通过工作台保存少量差异。命令行可运行 `py -3 -B chapter_host.py build 5` 或将末尾章节号换成 4。`--folder` 可选用另一份工程。启动工作台时可用 `--chapters` 指向含有 `ch4`、`ch5` 的替代目录。本机素材库提供地图静态预览，可运行副本负责动态演员、视差、遮罩、摄像机、机关和实际判定。

## 两章检验出的能力与边界

| 项目 | 本机章节工作台 | 轻量网页试玩 |
|---|---|---|
| 动态人物、剧情门禁、选项、回访和关键演出 | 执行本章 GameMaker 对象、实例代码和事件，可编辑源码重新生成 | 使用场景工程的旗标、条件、事件序列及已移植的互动 |
| 横版及特殊关卡 | 第 5 章的横版、悬崖和花城，以及第 4 章的攀爬、琴键和旋转塔使用各自的原作控制器 | 已加入重力、起跳、单向平台、冲刺、空中再次按住上键悬停、落坑重试。第 5 章悬崖冲刺图已接入 |
| 战斗与结算 | 两章保留原有战斗及原有战后分支 | 网页工程继续使用独立的场景战斗绑定 |
| 运行与导出 | 完整章节需要 Windows 本机运行程序。本次交付的章节工程可重复生成 | 原有离线 HTML 导出适用于轻量场景工程。完整章节尚无纯 HTML 导出 |
| 摆放与演出创作 | 可改现有实例的位置、门禁及演出脚本。场景平面图可点选物件 | 网页布景、事件和道具检查器可继续创建新场景。原生 GML 的复杂演出仍需编辑脚本 |

## 验收依据

| 内容 | 第 5 章 | 第 4 章 |
|---|---:|---:|
| 原始房间，含内部及测试房 | 252 | 328 |
| 摆放实例 | 12,489 | 13,952 |
| 可读事件和根脚本 | 11,853 | 10,268 |
| 核对的对象事件表 | 1,735 | 1,576 |
| 保持顺序的全局初始化程序 | 1,121 | 957 |
| 核对的运行程序、音乐、视频等外部文件 | 377 | 373 |

整章采用两条独立生成路径验收。第一条从编辑器工程重建全部资源并应用摆放和脚本。第二条直接读取本机 Steam 章节，仅加入相同的存档隔离、轨迹记录、返回工作台接线，以及当前工程明确保存的脚本修改。第 5 章额外修复了冲刺角色已移除时茶会特效仍访问角色的问题；核对结果列出了这一处修改。两个章节各自的完整输出均逐字节相同。由此可核对整章任意原有输入路径上的房间、门禁、台词、横版、战斗和事件资源是否在重建中丢失。另将两处真实剧情门槛和人物坐标改在临时工程中，编译后重新拆读，确认实际改动已进入游戏文件。

操作实测另行记录。两个章节都在工作台内用普通按键从空档进入开场。第 5 章另外走过卧室、走廊、早餐对话和离家，网页版悬崖关从左入口连续跨过三处断层到达下一间房，并验证落坑返回。两个章节都在独立段落预演中推进完最后一段演出，进入 `room_ed`。两次片尾使用预演档，从新档开始的接力跑图另有记录。 [第 5 章跑图记录](历史/第5章跑图记录.md)

重建核对和画面记录位于场景素材目录的 `chapters/ch5/verification.json`、`chapters/ch4/verification.json` 与 `chapters/验收/`。
