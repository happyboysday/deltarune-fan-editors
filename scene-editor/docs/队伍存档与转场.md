# 队伍、试玩存档与入战演出

《余火接力》是可编辑的两战样例。两场战斗的角色和道具 ID 有所不同，用于展示映射和继承。战斗原稿位于 `examples/battle/`。可从 V1.0 编辑器导出离线试玩，旧版的 HTML 和演示 MP4 位于场景素材目录的 `examples/`。 [样例工程](../examples/ember-relay.scene.json)

## 在工作台配置

1. 打开「队伍与试玩档」，启用共享队伍。为每位成员设置稳定 ID、初始及最大 HP。把初始数量写在「初始道具数量」里；「共享道具定义」只设置名称、治疗等属性。在遭遇里已定义的同一道具仍使用那场遭遇的效果。
2. 在「遭遇战与结算」绑定战斗。选择继承或单场独立，分别设置胜利、饶恕等结果的奖励数量。两边 ID 不同时，在「工程 JSON」填写 `partyMap`、`itemMap`；映射方向是 **遭遇中的 ID → 场景中的 ID**。
3. 选择「存档点」在画布放置它。选中后可改名字、是否回血、是否确认、读档落脚的房间入口，以及保存后要执行的事件。默认按 Z 确认并回满 HP；可设为接触即保存。要在战败后显示读档选择，把「队伍落败」设为「落败时提示读档」。
4. 默认入战演出支持经典冲入、普通淡入和直接切换。在某一场遭遇中可覆盖样式；时长、音效和演员起点可在 JSON 中逐场覆盖。样式、时长和角色坐标同时用于内置试玩和离线 HTML。

试玩时按方向键移动、Z 互动。在《余火接力》里，向右走到星光下方、朝上按 Z，选择「保存」。再向右接触巡逻员。第一战用星糖、躲避后击败或饶恕；向右走到工房门按 Z。进入下一间房便可检验剩余 HP 和道具。若落败，选「读取存档」回到余火灯。样例的余火灯关闭了回血，方便看清状态恢复。

「读取存档」从浏览器中的最近一份档开始。刷新或重开同一离线页面后，先点读档；不会自动覆盖当前试玩。「导出试玩档」保存 JSON，可在另一浏览器用「导入试玩档」继续。浏览器不允许持久存储时，仍可导出当次存档。建议作者为各独立作品设置不同的 `saveKey`；改名或移动 HTML 后可以用导出的档案迁移。编辑器「保存」存的是工程，试玩档独立存放。「试当前房间」只在这次临时预览内读写试玩档。

## 工程接口

以下为可合并到 `deltarune-scene/1` 工程的字段。可直接参考 [样例工程](../examples/ember-relay.scene.json) 中实际可用的 ID。

```json
{
  "campaign": {
    "saveKey": "my-work-v1",
    "defeat": "load",
    "party": { "kris": { "name": "Kris", "hp": 34, "maxHp": 48 } },
    "items": { "tonic": { "name": "星糖", "heal": 13 } }
  },
  "inventory": { "tonic": 2, "room_key": 1 },
  "battleTransition": { "style": "classic", "ticks": 25, "sound": true },
  "battles": {
    "patrol": {
      "encounter": "ember-patrol",
      "carry": "inherit",
      "partyMap": { "guest": "kris" },
      "itemMap": { "treat": "tonic", "prop_potion": null },
      "rewards": { "victory": { "badge": 1 }, "spared": { "badge": 1 } },
      "transition": { "actors": { "guest_actor": "player", "guard_actor": "guard_npc" } }
    }
  }
}
```

- `campaign.party`、`campaign.items` 都可选。有任一个时，引用默认继承；`carry:"isolated"` 可恢复该场自己的开局 HP 和道具。没有共享配置的旧工程保持原开局；独立战斗编辑器也保持其遭遇原值。成员省略 `hp` 时满血。
- 同 ID 的成员自动匹配，找不到的成员使用遭遇自身配置。临时成员可以显式映射为 `null`。道具默认按同 ID 匹配，库存中没有即为 0，`itemMap` 设为 `null` 时则保留该遭遇的道具数量且不会带回。场景专属道具可以只留在 `inventory`，不必把它们放进遭遇或共享道具定义。
- `campaign.items` 给未单独定义的遭遇补上物品条目，`name`、`text` 可用字符串或 `{zh,en}`，可设置 `heal` 和 `revive`。战斗剧本要额外增减道具，可在挂钩写 `{"cmd":"item","id":"treat","delta":1}`，其中 ID 是当前遭遇的 ID；要直接在场景治疗可用 `{"op":"hp","member":"kris","delta":10}`，全队回满用 `{"op":"hp","member":"party","full":true}`。
- 战斗结算时先写回实际 HP 和道具余量，再发放 `rewards`，之后才进入原有 `on` 剧情分支。若同时在 `on` 事件里用 `item` 加了同一份奖励，两笔会累加。TP、敌人状态、战斗变量按每场重置。逃离也带回已消耗的道具和 HP。
- `defeat:"load"` 可写在工程或单场引用上，单场优先。存在存档时可读档或重开；没有存档时可重开或返回当前场景，此时才继续原败北分支。用 `"scene"` 保留原来直接进分支的行为。战斗文件加载失败不提交状态或奖励。
- `transition.actors` 的键是**战斗演员 ID**，值是当前房间的场景实体 ID 或 `"player"`。适合有多个队员、多个敌人，或从对白开战的情况。未填时，主队员从场景玩家附近出发，敌人从触发者或右侧出发。经典演出的最终脚底坐标直接取战斗渲染器。时长为 8–90 步（30 步/秒），默认 25 步；`instant` 在资源就绪后直接交给战斗，`fade` 淡出场景后交接。
- 存档点最小写法是 `{"id":"lamp","kind":"savepoint","name":"余火灯","x":197,"y":121,"w":24,"h":26}`。`heal:false` 保留存档时的 HP，`confirm:false` 省去确认，`entry:"lamp_arrival"` 读档回本房间相应入口，未配置则回到保存的位置。记录时机在回血后、`event` 之前。读档还原旗标、库存、实体位置和显隐、已用机关及待触发计时事件；不会重新执行入口或存档点剧情。旧 `checkpoint` 仍是当前试玩的内存快照，不写浏览器存档。

## 原版观察和复验

本机拆包检查了第 1、2、4 章的通用入战。第 2 章 `scr_battle` 创建战斗背景与入场对象；`obj_encounterbasic.Create` 锁住场景输入、淡出场景曲并在队员原位放演出替身。背景逐步加深；替身跑向战斗站位，前约 10 个逻辑步留下残影，然后播放 `snd_impact` 与 `snd_weaponpull_fast` 并换到持武器姿态，再约 15 步后创建战斗控制器。第 4 章可在这段时间再加等待，特殊遭遇也可跳过一部分音效。编辑器沿用这套顺序，压暗原画面后完成冲入和落位，战斗 HUD 随战斗接管出现。进弹幕框时的灵魂动画由战斗引擎另外处理。

```powershell
node tools/scene.mjs validate examples/ember-relay.scene.json
node tools/verify-campaign.mjs "新版战斗编辑器目录"
node tools/verify-campaign-browser.mjs http://127.0.0.1:18945 "浏览器验收输出目录" "新版战斗编辑器目录"
```

浏览器走查包含真实按键入战、转场抽帧、战斗用药、跨房间和跨遭遇继承、落败后读档、刷新恢复与 JSON 导入。离线文件验收时拦截 HTTP/HTTPS 请求。老例程可使用 `?example=battle` 打开《纸门值班室》，或 `?example=workshop` 打开《回声工坊》。 [验收记录](历史/队伍存档与转场验收.md)

跟随队员进入战斗时使用其最后在地图上显示的脚底坐标。队列顺序不同或有条件出场的角色可在房间的 `followers` 条目设置 `id`，再用 `transition.actors` 把战斗演员映射到该 ID。落点与战斗的 `settings.partyLayout` 或演员自由站位一致。
