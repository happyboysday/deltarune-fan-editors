# 插件开发 · API 1

可以从仓库自带的「萤火小径」开始。启动编辑器时，在原有参数后加上 `--plugins examples/plugins`，打开 `/?project=/plugins/fireflies/demo.scene.json`。选择「试玩」，向右走，沿途收集三只萤火。房间检查器可以修改时限，选中萤火可以修改收集半径，「添加萤火」按钮会生成新的实体 ID。点击「离线 HTML」即可得到同一个玩法的单文件版本。

## 目录与清单

每个插件占用一个子目录，目录名等于 ID。内置插件位于 `studio/plugins/builtin/`。用户目录默认是数据目录下的 `plugins/`，也可通过设置页或 `--plugins` 指定。示例的完整实现见 [fireflies](../examples/plugins/fireflies/)。

```text
plugins/
  fireflies/
    plugin.json
    runtime.mjs
    art.mjs
    editor.mjs
    demo.scene.json
```

```json
{
  "id": "fireflies",
  "name": "萤火收集",
  "version": "1.0.0",
  "apiVersion": 1,
  "description": "在限时内收集萤火。",
  "author": "Scene Studio",
  "runtime": "runtime.mjs",
  "editor": "editor.mjs",
  "provides": {
    "modes": ["fireflies.collect"],
    "entities": ["fireflies.light"],
    "actions": ["fireflies.finish"]
  },
  "dependencies": []
}
```

| 字段 | 约定 |
| --- | --- |
| `id` | 小写 ASCII 字母开头，可含小写字母、数字、连字符，最多 64 个字符。内置 ID 已占用。 |
| `name`、`description`、`author` | 必填非空文本。 |
| `apiVersion` | 整数 `1`，主版本精确匹配。破坏已有钩子签名时提升 API 主版本。 |
| `version` | 三段非负整数，每段最多六位，例如 `1.10.0`。最低版本按三段数值依次比较。 |
| `runtime`、`editor` | 目录内的相对 `.mjs` 路径，文件名及目录段用英文字母、数字、下划线或连字符。`runtime` 必填，`editor` 可省略。 |
| `provides` | 三个数组均必填，可为空。第三方名称使用 `插件ID.本地名`，本地名以字母开头，可含数字、连字符、下划线。各表内名称唯一，必须与默认导出的实现一一对应。 |
| `dependencies` | 可省略。每项形如 `{"id":"other","minVersion":"1.2.0"}`。加载器先加载传递依赖，报告缺项、版本不足及循环链。 |

工程根字段 `"plugins":[{"id":"fireflies","minVersion":"1.0.0"}]` 选择该工程的插件及依赖。省略字段会启用内置地下城与赛车；显式空数组只启用基础玩法。混用时在数组中同时列出相应的内置 ID，如 `dungeon`。打开另一个工程会重新选择可用的钩子。工程里继续使用原来的 `room.mode`、`entity.kind` 和 `action.op` 字段。

## 安装与启用

在编辑器首页打开「插件管理」，输入含 `plugin.json` 的本机文件夹绝对路径，或上传最大 20 MiB 的 ZIP。ZIP 可直接包含插件清单和文件，也可包含一层外包目录。安装使用 T2 的清单和 API 版本校验，同时检查入口存在、文件类型和目录边界。安装包内允许 `.mjs`、`.json`、`.png`、`.gif`、`.jpg`、`.jpeg`、`.webp`，解包后最多 64 MiB。符号链接、目录联接和重复冲突路径会被拒绝。

安装时以清单 ID 命名插件目录。已有 ID 会返回冲突。用户插件默认启用，曾登记的启用状态会沿用。可在「插件管理」停用、启用和卸载用户插件。卸载会把目录移入数据目录下的 `plugins-trash/`。工程要求停用或缺失的插件时，可按编辑器提示安装或启用，然后重新打开工程。内置插件始终启用。

## 运行时入口与生命周期

`runtime.mjs` 默认导出普通对象。按名称将实现放入 `modes`、`entities`、`actions`，空表可省略。可选的入口钩子 `entityDefaults({project,entity})` 可先展开工程级实体模板，再调用具体实体类型的 `resolve`。每个钩子只接收一个上下文对象，按需解构。所有运行时、校验、绘制钩子均须同步返回。模块顶层应能在 Node、浏览器和导出的 HTML 中执行。

```js
export default {
  modes: {
    'fireflies.collect': {
      label: '萤火收集',
      enter: ({room}) => ({left: room.timeLimit ?? 300}),
      step({local, move}) {
        if (local.left > 0) { local.left--; move(); }
      }
    }
  }
};
```

| 模式钩子或属性 | 调用时机与用途 |
| --- | --- |
| `label`、`help`、`face` | 编辑器模式名、试玩操作提示、入口省略朝向时的默认值。 |
| `enter(ctx) → local` | 已放置玩家，进入房间或切换模式时创建该世界独有的局部状态，可从 `state[state.mode]` 读取。重新入场、读档时会重建。 |
| `step(ctx)` | 30 Hz。在允许移动的 tick 先推进模式，再按活动实体顺序推进实体，随后处理事件队列，最后更新跟随镜头。战斗、菜单和阻塞事件沿用原有时序。缺省使用通用移动。 |
| `exit(ctx)`、`retry(ctx)` | 切换房间或模式、恢复快照、重开和销毁时释放旧局部状态。平台落坑回到入口后调用 `retry`。 |
| `playerBox(ctx) → {x,y,w,h}` | 覆盖玩家碰撞矩形；基础盒以玩家中心和半径计算。 |
| `platform`、`platformLabel`、`customDash`、`movementProfile(ctx)` | 横版移动默认值包括 `speed, acceleration, gravity, jump, fallSpeed`。可设面板标签、自行处理冲刺，或返回含 `walkSpeed,runSpeed,jump` 的移动配置并启用脚底贴地。 |
| `keys`、`toolKey`、`scriptField` | 可将键盘 `KeyboardEvent.code` 映射到已有输入名。自由行动时使用该映射。`toolKey` 启用 Shift 冲刺、菜单键作工具键及对应触屏控件。`scriptField` 可指定时间线字段，优先于通用 `navScript`。 |
| `debug({local})` | 返回可序列化的模式摘要，出现在演练调试接口的同名字段。 |

运行时上下文中的 `project, room, state, player, local, tick, radius` 描述当前工程、房间和世界。把配置当作只读数据。`active` 是活动实体列表，`input.hold` 和 `input.press` 是按键名的 Set，在有输入的推进阶段可用。

| 上下文方法 | 用途 |
| --- | --- |
| `move()` | 执行一次通用移动、更新接触并处理互动。自定义模式可以在 `step` 中调用一次。 |
| `platformMove(x,drive?)`、`interact(onAct?)` | 分开驱动横版移动和互动。横轴通常为 −1、0、1。`drive` 可指定 `vx`、锁住跳跃的 `lock`、暂停垂直运动的 `suspend`。 |
| `run(eventId)`、`mark(entity,patch)` | 将工程事件加入队列；记录实体的运行时变化，如 `mark(entity,{hidden:true})`。直接改 `active` 列表中的临时副本不会持久保存。 |
| `cameraSnap()`、`shake(intensity)`、`retry()` | 将镜头对齐房间焦点、触发震屏或回到平台重试入口。固定镜头可通过 `state.camera` 控制。 |
| `rng()` | 返回每个世界独立的确定性伪随机数，范围为 [0, 1)。 |

确定性逻辑只使用输入、`tick` 和 `rng()`。禁止在模拟中使用 `Math.random()`、`Date`、实时时钟、计时器及异步 I/O。把每局数据放进 `local`，不要存进模块级变量。绘制次数取决于显示器和编辑器刷新，绘制时不得推进状态或消耗模拟 RNG。需要随通用检查点恢复的进度写入 `state.flags`、库存或实体变化；内置模式沿用 V0.6 读档时重新创建模式状态的行为。

## 实体、动作与校验

| 注册位置 | 钩子 |
| --- | --- |
| `entities[name]` | `label` 显示在检查器。`resolve({project,entity})` 可返回展开默认值后的实体。`step({...ctx,entity})` 推进行为。`draw({...draw,entity,tick})` 用房间坐标绘制。`pose({...draw,entity})` 可返回用于深度排序的位置和高度。`ignoreSolid` 跳过通用固体判定，`customEvents` 启用自定义事件字段面板。 |
| `actions[name]` | `execute({...ctx,action})` 由原有事件解释器执行，适用于普通事件和分支中的动作。通过 `run` 可接续工程事件。 |
| 模式、实体、动作各自的 `validate(ctx)` | `value` 是房间、实体或动作，`path` 是该值在工程中的路径。房间、实体验证还提供 `room`。用 `error(path,message)` 或 `warn(path,message)` 返回中文诊断。 |
| 入口对象的 `validation(ctx)`、`validateRoom(ctx)` | 每次整工程校验先调用一次 `validation`，可校验公共配置、返回本次检查的辅助对象。后续钩子从 `schema` 读取。每个房间都会调用已选择插件的 `validateRoom`，可检查跨模式使用的字段。 |

校验上下文提供 `project, assets` 和路径感知的工具。常用的有 `opt(obj,key,path,check)`、`num(value,path,min,max,integer=false)`、`str(value,path,max=512)`、`bool(value,path)`、`id(value,path)`、`one(value,choices,path)`、`arr(value,path,max)`、`obj(value,path)`。另有 `color,source,frames,sprite,evt` 分别检查颜色、图片路径、帧组、工程素材 ID、事件 ID；`reference(table,value,path,label)` 查表。内置校验还用到 `own(obj,key),record(value),range(min,max,integer?),choice(...values),pair(check),animSettings,seconds(value,path),duration(value,path),timeline(rows,path,roomScoped?)`。

例如示例动作调用 `id(value.flag,path+'.flag')` 检查旗标名称，执行时写入 `state.flags[action.flag]=true`。未识别的模式、实体或动作会在具体字段报告「缺少插件」和提供者 ID。

## 绘制与素材

绘制上下文包含 `ctx, project, room, state, local, art, assets, cam, viewport, edit, hideHud`。画布由主机管理，图片通过 `art.images.get(url)` 取得。编辑预览中可能没有玩家或 `local`。实体绘制与房间坐标对齐。各个绘制钩子应自行配对 `ctx.save()/restore()`。

| 钩子 | 顺序与坐标系 |
| --- | --- |
| `drawWorld` | 试玩时接管整个逻辑视口，可用于伪 3D 等自行绘制世界的玩法。定义后负责本模式的地形与角色。 |
| `drawBackground` | 通用房间绘制中，场景底图后、地图背景层前，使用房间坐标。 |
| `animationTick`、`feet`、`groundKinds` | 可改用模式的动画时钟，指定玩家脚底偏移，或为房间指定先于角色绘制的实体种类数组。 |
| `drawTrail`、`drawPlayer` | 分别在深度排序后的角色列表前和每个玩家角色处调用。上下文另有 `drawPlayer(entity,sprite?,tint?)`；`drawPlayer` 钩子返回 true 表示已完成该角色绘制。若只需替换角色贴图，可实现 `drawSprite({...draw,entity,sprite,tick,feet})`，绘制成功时返回 true。 |
| `drawEffects`、`drawForeground` | 通用房间中分别位于角色之后和前景之后，均在光照之前。接管世界绘制时，前景在 `drawWorld` 之后，沿用逻辑视口坐标。 |
| `drawHud`、`drawOverlay` | HUD 在震屏变换之外，仍使用逻辑视口。覆盖层位于系统 HUD、对话、淡入淡出及演出之后，使用实际画布尺寸。编辑预览和隐藏 HUD 时跳过这两层。 |
| 入口对象的 `roomAssets({project,room,needs})`、`preload({project,rooms,needs,assetsIn})` | 向 `needs` Set 添加每张可能用到的图片 URL，包括所有动画帧。`rooms` 是本次需要加载的房间数组，`assetsIn(asset)` 展开标准素材。主机统一预载和打包。 |

自带图片可放在插件目录下，使用稳定的逻辑路径，例如 `/plugins/fireflies/art/light.png`。支持 PNG、WebP、JPEG 和 GIF，也可引用工程素材或直接用代码绘制。预载和导出后仍用同一逻辑路径索引 `art.images`。

## 编辑器入口

`editor.mjs` 默认导出面板钩子对象。编辑器会在工程切换时重新挂载工具并刷新检查器。运行时入口独立于 DOM。

| 钩子 | 参数与用法 |
| --- | --- |
| `mount({root,button,project,room,commit,status,changeLayer})` | 每次挂载获得独立容器。`project()`、`room()` 返回当前对象。`button(label,action)` 注册工具按钮并捕获回调异常。`commit(nextProject,layer?,part?)` 校验副本、记录撤销并刷新。`status(text,bad?)` 显示提示。`changeLayer(id)` 切换编辑层。 |
| `roomPanel({project,room,field,mk,numberField,update})` | 房间检查器重建时调用。按 `room.mode` 选择适用的面板，使用 `numberField(room,key,label,min,max)` 绑定数值字段。 |
| `entityPanel({project,room,entity,field,mk,numberField,eventOpts,dropdown,update})` | 选中实体时调用。使用 `field(label,control,fullWidth?)` 插入控件，`mk(tag,text?,properties?)` 创建节点，`update(obj,key,value)` 记录撤销并更新。事件选择器可组合 `dropdown(options,current,onChange)` 与 `eventOpts()`。 |
| `layer({room,layer})`、`controls({project,room,layer})`、`grid({project,room,ctx,model,layer,paint})` | 模式属性 `layeredGrid:true` 允许物件和入口保留底下的地形。专用的分层编辑器可返回当前层、更新工具区和绘制网格预览；`paint()` 请求重绘。 |

## 加载、离线导出与调试

- `GET /api/studio/plugins` 返回 `plugins` 数组。每项包含 `directory,builtin,base,manifest,errors,enabled,source,projects`。清单解析失败的条目保留目录名与错误，`projects` 列出当前打开且依赖该插件的工程。使用 `GET` 或 `HEAD /plugins/<id>/...` 读取启用的用户插件目录内的模块、JSON 和图片。
- Node 工具可运行 `node tools/scene.mjs validate examples/plugins/fireflies/demo.scene.json --plugins examples/plugins`。嵌入应用可从 `studio/plugins.mjs` 导入 `registerPlugin(manifest,runtime,{base,editor}?)`，或使用 `loadPlugins(requirements,discovered,importModule,{editor}?)` 加载依赖后再调用 `validateProject` 或 `createWorld`。`projectPlugins(project)` 返回本工程的已解析表和诊断。独立的清单校验函数位于 `studio/plugin-manifest.mjs`。
- 发布用的运行时模块使用相对路径和显式 `.mjs` 后缀。导出器解析整个模块的静态 `import` 和 `export … from`，检查模块语法、依赖文件和导入名称。依赖可以多层、可以共享。动态 `import()` 和 npm 裸包名会导致导出失败。图片交给素材预载钩子。
- 编辑器导出时从播放器和所选插件的运行时入口递归收集模块，将 JS、场景、图片、UI 资源放入单 HTML。插件编辑器入口只在工作台加载。在命令行可用 `node tools/export-example.mjs 服务地址 工程文件 输出.html --plugins 插件目录`。
- 调试确定性可使用 `createWorld(p,{autoplay:true})` 并调用 `world.step()`，或传入 `{hold:[...],press:[...]}`。静态清单诊断见发现接口，工程字段诊断见编辑器校验区。钩子异常带有插件 ID、扩展点和消息；校验异常算作工程错误，运行时异常跳过本次回调。控制台保留错误，即使状态栏随后更新。
- 插件是本机代码。浏览器中可访问页面，服务端保存校验及命令行工具会在 Node 中执行其运行时模块。只安装信任来源的插件。目录限制适用于 HTTP 文件服务；钩子异常隔离用于防止编辑器因普通插件错误而中断。
