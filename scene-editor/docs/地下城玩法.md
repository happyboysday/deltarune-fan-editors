# 横版地下城作者手册

打开 `examples/dungeon-demo.scene.json`，从「暮色断崖」往右走。途中可以踩上浮岩、测试三段斩，或在星点记录进度。尽头的粉门通往「城顶回廊」。穿过柱廊，在最后的星点按 Z，看到抵达对白即完成示例。

## 建房与摆放

1. 复制示例工程，在房间设置里选择地下城模式。房间尺寸用逻辑像素，入口写在 `entries`，工程用 `start.room` 和 `start.entry` 指定起点。示例两个房间分别为 1120×480 和 960×480，镜头为 640×480。
2. 设 `grid.size`。示例用 40，对应官方瓦片原尺寸。选「从官方瓦片集新建方块」，选择城顶或断崖。在同层用实体地面铺出连续路线；浮台选 `oneway`，角色可以从下方跳上去。入口放在地面上方，给角色留足身体空间。
3. 在背景层画远墙，在前景层画柱身。切换到「敌人与物件」放敌人、门和检查点。门要填写目标房间及入口。检查点可执行事件；战斗死亡后的重试位置由本房间的 `platform.retryEntry` 指定。
4. 在角色面板选「从官方 Kris 新建角色」，把角色 ID 填入 `player.fighter`。要让某房间临时换人，设置该房间的 `dungeonConfig.fighter`。两处均留空时使用旧工程的内置 Kris。
5. 试玩时用左右移动、↑ 跳、按住 X 奔跑。Z 互动或攻击，Shift / V 闪避。C、F、Q、E 对应技能 1 至 4。示例依次为金星、架剑、破阵、振作。Esc 用于返回检查点。脚本使用逻辑键名，旧 `tool` 对应 `skill1`。

## 柱廊的遮挡

在 `roof`，第 4 列（从 0 数）有背景砖、柱头与前景柱身。角色经过柱身时会被遮住。旁边第 5 列的浮雕是 `actor` 层，排序键为 `y + h + depth`。把该浮雕的实例 `depth` 从 6 改为 −6，再从旁经过，观察脚底跨过排序线时谁盖住谁。排序参数不会移动图片，也不会增加碰撞。

同一格可分别放背景、同层、前景、碰撞和物件。每块使用房间坐标，左上角与网格对齐。零件定义给出默认层；单块可用 `layer`、`depth`、`activeWhen` 覆盖。始终遮住剑光的栏杆用 `front`。前景装饰通常用 `solid:"none"`，需要挡路时另设碰撞。

## 动作、攻击和技能

动作槽可填素材 ID 或带 `frames` 的内联对象。准备离线工程时，推荐像示例一样将所有帧登记到 `assets`，让打包器收集图片。帧按数组顺序播放，`ticks:4` 表示每帧保持 4 个逻辑 tick，每秒 30 tick。用 `anchor:"feet"` 锚定脚底，`offset:[dx,dy]` 调原点；原图朝左时设 `flip:true`。走、跑、待机和下落通常循环，挥剑动作通常停在末帧。缺跑步可回退走路，缺下落可回退跳跃。

地面连段按 `attacks` 数组排序。每段填写 `windup / active / recovery`、伤害、面朝右时相对于脚底的矩形 `hitbox:{x,y,w,h}`。向上为负 y。把斩光放到 `effect`，使用与主体相同的帧时长和原点。用 `comboWindow` 设置收招后可接下一段的时间，用 `hitstop` 调命中停顿。空中招式放在 `airAttack`。闪避的总时长和无敌时间以 tick 计，`cooldown` 以秒计。

**画面缩放与判定分别设置。** 素材条目和内联动画均可写 `scale`，默认 1，有效范围 0.25–8。锚点和 `offset` 使用原图像素，绘制时一起放大。例如 Kris 待机图为 34×36，`scale:2` 后画布占 68×72 房间像素；`offset:[-7,0]` 显示为左移 14 像素。官方敌人与斩光也设为 2，40×40 的原图瓦片保持一格。

`box`、`hitbox`、技能尺寸、射程和移动速度都直接填写房间单位。Kris 身体框为 36×68，金星的飞行判定为 24×24，速度为每 tick 8 像素。单独调整美术的 `scale` 时，这些数值保持作者填写的大小。示例的敌人按一列两格放置，实体显式填写 40×80；省略实例宽高时采用类型的 `box`（48×60 或 48×64）。

每个技能使用独立的 `id`、`input`，配置 `name`、`type`、`cooldown`、`cast`；可指定 `anim`、`sprite` 与 `sound`。在同名子对象内填写参数：

| 类型 | 子对象参数 | 用法 |
| --- | --- | --- |
| projectile | speed、life、w、h、damage；可选 pierce、gravity、count、spread | count 大于 1 可扇形齐射 |
| area | x、y、w、h、damage、ticks；可选 knockback | 相对脚底的持续判定 |
| parry | radius、window；可选 reflect、stun | 近身反弹、眩晕 |
| dash | speed、ticks、damage；可选 invulnerable | 带伤害的突进 |
| heal | amount | 恢复角色 HP |

例如，将示例第一个技能替换为下列对象，即可用 C 试验一圈持续 4 tick 的近身斩：

```json
{"id":"ring","name":"回旋斩","input":"skill1","type":"area","anim":"kris_slash1","cooldown":1,"cast":1,"area":{"x":-60,"y":-80,"w":160,"h":80,"damage":11,"ticks":4}}
```

## 数据速查

| 位置 | 常用字段与约定 |
| --- | --- |
| fighters.ID | hp、box（宽高）、walkSpeed、runSpeed、jump、anims、attacks、airAttack、comboWindow、dodge、skills |
| enemyTypes.ID | 调色盘用 sym、label、cells、color；战斗用 hp、damage、box、speed、contact、gravity、aggroRange |
| enemyTypes.ID.ai | patrol 两端巡逻；chase 警戒范围内追击；turret 原地射击；flyer 空中漂移 |
| 敌人的进攻 | melee 设置距离、前摇、有效期、后摇、判定框和伤害；shoot 设置 interval、delay（秒）、speed、range、count、spread、sprite、color；onDefeat 引用事件 ID |
| rooms.ID.entities[] | kind 为 actionEnemy 时，enemyType 指向类型，x、y 是实体左上角。同名字段可覆盖类型默认值 |
| tileParts.ID | sym 用一个小写字母或数字；cells 为正整数宽高；sprite 引用素材；layer 为 back、actor、front；solid 为 none、solid、oneway |
| rooms.ID.tiles[] | part 指向零件；x、y、w、h 用像素。原有 sprite 与 front 写法仍有效 |
| rooms.ID.platform | gravity、jump、fallSpeed 等物理参数与 retryEntry。使用 fighter 的角色可配置自己的 jump |
| rooms.ID.parallax[] | src、speedX、speedY、height、repeatX 控制视差远景 |

敌人符号用大写字母，避开内置符号和现有 gridParts。地图中的点表示空格。多格物件从左上角记录，覆盖格依照该层文字地图输出。查看当前工程符号请用 `parts`。

## 命令行

在工程根目录运行以下命令，使用示例的副本练习。

```powershell
Copy-Item examples/dungeon-demo.scene.json my-dungeon.json
node tools/scene.mjs parts my-dungeon.json
node tools/scene.mjs dungeon init my-dungeon.json annex --cols 24 --rows 12 --size 40 --write
node tools/scene.mjs grid show my-dungeon.json roof --layer front
node tools/scene.mjs grid show my-dungeon.json roof --layer front | Set-Content -Encoding utf8 front.txt
node tools/scene.mjs grid apply my-dungeon.json roof front.txt --layer front --write
node tools/scene.mjs validate my-dungeon.json
node tools/verify-dungeon.mjs
```

`grid show/apply` 支持 collision、back、actor、front、objects。写回前可省略 `--write` 试校验，或用 `--out` 另存。D3 独立克隆可用 `node tools/verify-dungeon.mjs --static` 验证数据；完整验收还会驱动世界和分层文字地图。

运行 `python studio_server.py --port 18973` 后，从工作台导入 JSON 试玩。独立 HTML 可用 `node tools/export-example.mjs http://127.0.0.1:18973 my-dungeon.json my-dungeon.html` 导出。

## 官方素材和手感依据

- V0.4 的 `/official/` 直接指向官方库。瓦片使用已有 `/a-files/exports/derived/tiles/ch5/…` 路由，服务器按 V0.4 索引的 source_rect 从官方 PNG 读取 40×40 内容。两侧各有 2 px 边界，源格步长 44。裁切 URL 的编号从 1 起算。工程里无需单独保存切图。
- 断崖取自 `room_dw_cliff_twirlflowerplatforming` 的 `tiles_cliff_dark_new`，城顶取自 `room_dogplatforming` 的 `bg_dw_castletop_tileset_new`。从图集左上角按行自 0 计数，后者的 5、45、122、22、2、11 号格依次作为砖壁、城墙、窄台、柱身、柱头、浮雕。图集使用记录见官方库 `maps/ch5/rooms_render.json`；实际物件在同目录的 `rooms_instances.json`。示例使用这两个房间中的夕照和远柱素材重新设计路线。
- 第五章 `obj_plat_entity.Create` 将两轴设为 2 倍，横向保留朝向符号；`obj_plat_player.Step` 根据左右输入设 `image_xscale` 为 −2 或 2。Create 的 `hspeed_max=9`、`jumpheight=20`、`dashspeed=11` 直接作用于水平、垂直速度；重力为每步 1.25。示例沿用这组房间单位，另设步行速度 6。原作自动奔跑时每步推进 0.25–0.5 帧，走、跑复用 6 张 run 帧，各保持 4、2 tick。跳和下落按 Step 使用 `spr_kris_jump_up/down`。
- **闪避与倒下。** Step 的 `static_dash` 自动冲刺使用 `spr_kris_plat_run`、`image_speed=0.5`；示例闪避取同一组六帧并配残影。倒下选用第五章收录的暗世界倒地姿态 `spr_kris_fallen_dark`（共一帧）。这是给 `down` 槽的作者映射，落地受击仍用横版控制器的 `spr_kris_plat_hurt_ground`。倒地图片底部即接地点，按脚底锚定。
- 原点换算按 Create 中的强制动画对齐公式。右向脚底偏移为 `[宽/2-OriginX, 高-OriginY-18]`，其中 18 是待机画布高度的一半。地面斩的画布为 99×90、原点 (43,43)，空中斩为 99×90、原点 (52,41)。
- 原作挥剑的 image_speed 为 0.6，于帧号 1、5、9 建立判定。预设按 0–3、4–7、8–12 拆地面三段，主体与 foreground 同步，近似为每帧 2 tick。地面判定图三帧的非透明外接框（含端点）为 (25,12)–(82,66)、(50,6)–(82,76)、(19,0)–(92,72)。空斩用五帧并集 (15,6)–(86,77)。两张判定精灵的原点均为 (43,43)。左上角先减去 (43,61)，再把相对坐标和宽高都乘 2，直接写入工程。例如第一段为 `{x:-36,y:-98,w:116,h:110}`。契约每招使用一个矩形，因此边角透明处也计入判定。空中技能使用完整 17 帧素材；原作部分空中状态会直接从第 8 帧起手。
- 七组敌人动画的完整原帧随编辑器提供，路径为 `/studio/art/dungeon-ch5/<sprite>_<NNN>.png`；网页试玩和离线打包共用这些 URL。忍甲虫主体和 pose 各一帧，继续使用官方库。拼图兵、棋兵继续使用 `enemy-animations/enemies` 的完整帧组。
- Kris 的 turn、hurt_ground、hurt_air、pose、fallen_dark 和共用弹体 plat_bullet_yellow 经第五章 data.win 核对均为一帧。它们沿用现有链接。
- 维护者可从编辑器根目录调用 UTMT 加载第五章 data.win，执行 `tools/dungeon-reference.csx`，将标准输入重定向自 NUL。脚本把角色原点和反编译结果写在 `.research/`。

| 敌人素材（省略 spr_ 前缀） | 帧数 | 每帧 tick 与依据 |
| --- | ---: | --- |
| forange_largeglove | 6 | 4；orange_miniboss 的 Create 初始化 image_speed 为 0.25 |
| forange_glove | 3 | 2；参考 smallglove 的 Step 中 0.5 的运动段，原作另有手动选帧 |
