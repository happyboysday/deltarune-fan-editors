# V0.6 场景工程接口增量

仍使用 `deltarune-scene/1`，原工程无需升级。V0.6 移植所需的新字段：

| 字段 | 用途 |
|---|---|
| `room.layout` | 随项目提交的布景 ID。编辑器从本机同源接口按房间读取。与 `room.map` 二选一；「内嵌布景」把它转换成可单独保存和编辑的 `map`。 |
| `room.view: {w,h}` | 房间的实际逻辑视口，仍绘入工程 `viewport`；保持长宽比例。画布编辑、游戏镜头和战斗转场共同使用同一变换。 |
| `room.playerArt`、`room.playerFeetOffset` | 房间进入后切换玩家素材和绘制足点。素材可含四方向的 `idle_*`、`walk_*`。 |
| `room.followers: [{sprite,delay,when?}]` | 以玩家实际移动轨迹作为队员队列。可用条件选择何时显示角色。切房或读档后从当前位置重新建立跟随轨迹。 |
| `room.tool: {item,range,width,ticks,sprite?,variants?}` | 有指定道具时按 C 向面朝的方向施用。阵列 `variants` 每项可按条件切换 `range` 和 `width`。目标物件设 `toolTarget:true`、绑定事件；`once:true` 的成果会跟随试玩存档。 |
| `condition.compare` | 数值旗标可用 `lt/le/gt/ge`，或显式 `eq/ne`。原有 `{flag:"…",is:true}` 语义保持。 |
| `entity.draw:false` | 保留接触体及互动脚本，由原图层负责外观。编辑时仍能选中触发体。 |
| `door.fade`、`savepoint.beforeEvent` | 把门的既有淡入时长和存档前对白从程序提到场景。它们不替换已有的转场能力和保存结算事件。 |

「工程 JSON」可进行精确编辑。「配置工具」和物件的「仅手持工具触发」可直接使用画布旁检查器。
