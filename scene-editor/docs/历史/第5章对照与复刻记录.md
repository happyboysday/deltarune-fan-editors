### 覆盖与验证

- 252 个房间记录全部建档；逐条排除了系统、调试、模板、影片等 55 条，留下 **197 张**面向场景复刻。
- **196 张**已导入，其中 **187 张**有可见源布景。当前声明 **168 张**含可执行的移植行为；以四像素静态可达检查并要求有源布景计，**163/197 张（82.7%）**能从一个声明入口走到至少一个对应触发点。这一数字不等于 163 张都逐室完成了实机流程。
- 326 个带实际目标的门、16 个存档点、92 个有源对白的交互，以及 957 个额外触发实例。957 包含同类植物的多个实例，不是 957 种玩法。静态通路检查检出 12 扇门和 7 个交互点的碰撞、门禁或条件问题，留在清单内。
- 浏览器实测走出 Kris 房间、目标房间按需加载、搜索房间、内嵌并打开原图层编辑、加载旧 V0.5 样例。自动输入复放覆盖四道连续门、回床选择两支、先对白再保存与读回、取壶喷水和花城入口触发。旧样例的栅栏机关、战斗胜利/饶恕/落败/逃离与两战读档继续通过。
- 第 5 章复刻是可编辑的探索工程，**目前不能完整首通原作整章**。没有移植的关卡脚本、战斗、任务后置生成和回溯剧情仍用源 ID 标出。只保留了画面的场景不算已移植玩法。

记录位于场景素材目录的 `chapter5/` 下。逐室覆盖见 `coverage.json`，原版对象和脚本索引见 `source-index.json`，几何与素材检查见 `access-audit.json`，自动复放见 `场景复放.json`，浏览器检查见 `验收/浏览器验收.json`。

### 重建

由 `tools/ch5-extract.csx`、`tools/ch5-extract-art.csx` 和 `tools/ch5-extract-layer-assets.csx` 分别从本机 `data.win` 读取布局、选取脚本、逐帧图片和独立精灵图层。环境变量 `DR_CH5_OUTPUT` 指向新的临时目录。对每个脚本运行 `UndertaleModCli.exe load "…/chapter5_windows/data.win" -s "脚本路径"`，不指定输出游戏文件。

然后在本项目目录运行：

```text
py -3 tools/import-chapter5.py --base "V0.4 目录" --game "chapter5_windows 目录" --facts "临时拆包目录"
node tools/verify-chapter5.mjs
node tools/audit-chapter5.mjs http://127.0.0.1:18946 chapter5/access-audit.json
```

导入器的 `ch5_gml.py` 只识别用于本工程的少量 GML 语句；未识别语句不在浏览器里执行。带步骤和镜头的复刻在 `ch5_authored.py`。不要在有未另存的编辑稿时重新生成模板。复验临时文件和反编译缓存可清理，保留工程、来源索引与原始素材依赖。
