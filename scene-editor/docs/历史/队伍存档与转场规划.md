# 队伍状态、存档点与入战转场｜V0.5 实施规划

目标：把连续遭遇变成同一趟冒险。先校对原版入战和存档行为，再实现队伍、道具、读档和转场。沿用 `deltarune-scene/1`，旧工程可原样打开，独立战斗仍按其自身文件开局。

| 顺序 | 实现 | 验收 |
|---|---|---|
| 1. 队伍与库存 | 场景维护稳定成员 ID、当前/最大 HP、库存。可在单场指定继承或独立，必要时映射成员/道具 ID。继承型战斗注入队伍 HP 和战斗可用库存；道具消耗、战中获得和结算奖励按实际最终数同步回场景。独立战斗与旧工程不改原开局。 | 第一战受伤、用药并拿奖励；第二战开局可见相同 HP、剩余道具和奖励；没有重复补货，场景专属道具保留。 |
| 2. 存档与落败 | 添加可摆放的存档点，可选择是否回满 HP，配置名称及读档入口。记录场景位置、旗标、实体进度和队伍库存到单独的试玩档；可跨刷新继续，也可导出/导入档案。开启落败读档的工程会显示读档或重头开始；没有存档时能重开。 | 保存、改变 HP/道具/进度、战败读档，精确回到存档时状态。在线编辑预览、离线试玩均可恢复；旧检查点行为保留。 |
| 3. 入战演出 | 以本机原版第 1/2/4 章通用入战为参考：先锁输入、压暗旧场景，角色短促就位并留残影，响起入战音效后交给战斗画面。可选普通淡入和直接切换，并允许单场覆盖。战斗内部灵魂飞入战斗框照常由战斗引擎播放。 | 抽帧确认场景起点、残影、落位、战斗画面连续；不同窗口比例无跳位；两类触发共用演出，触发键不会穿透。 |
| 4. 编辑与交付 | 视觉界面可设队伍、战斗继承、奖励及存档点。更新接口、模板、两场连续遭遇样例、离线 HTML 与 MP4。 | 通过真实战斗和浏览器测试，覆盖关页/刷新恢复、落败返回、失败读档、旧场景和旧战斗导出回归。 |

范围：不改正版文件和《大魔术秀》定稿；TP、战斗临时变量和敌人状态各战独立。试玩存档与作者工程存档分开。示例以玩家确认存档为准，不在每次结算后自动覆盖。
