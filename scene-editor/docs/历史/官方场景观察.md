
# DELTARUNE 官方场景观察与 V0.5 对照

以本机 Steam 安装的第 1–5 章 `data.win` 为资料。用 UndertaleModCli 读档，观察房间、实例、图层以及少量对象和脚本；没有向游戏安装或存档写入数据。[官方网站](https://deltarune.com/)和 [Steam 官方实机画面](https://store.steampowered.com/app/1671210/DELTARUNE/)可对照观感。下面的实现判断来自本机资源。

| 官方观察 | 编辑器怎么做 |
|---|---|
| 第 2 章 `obj_mainchara_Step_0` 对 X、Y 方向的移动分别做固体碰撞检查。`Step_2` 另算跟随视口并限制房间边界。 | 房间边界、墙、推块与 30 Hz 移动；房间尺寸与视口独立，镜头可跟随、固定或由演出平移。 |
| 第 2 章 `obj_doorAny` 的目标房间和入口可以按实例状态计算；只看到门的原始位置不足以知道它在剧情里通向哪里。NPC 的对象事件也会读取进度再决定对白。 | 门和出生点可预览为候选，目标与入口由作者设置。NPC、门、触发区可绑定条件、对白与道具；对白中可提供玩家选项。 |
| `scr_cutscene_commands` 将动作拆成对话、角色移动、镜头等命令，事件之间可以等待或衔接。 | 用指令序列编排对白、显隐、换图、人物和镜头补间、定时触发和转场。 |
| 第 3 章可找到独立的冰面棋盘控制器 `obj_board_icepuzzle_controller1`，以及处理节奏场面的 `obj_rhythmgame_event_manager`。 | 移动可切换为惯性滑行；推块和踏板可联动。节奏事件可设置拍点、键位、容错和通过/失败分支。 |
| 第 4 章 `obj_climb_kris_Step_0` 有单独的方向输入缓冲和攀爬状态；第 5 章 `obj_wateringcan_Step_0` 区分点按、持续喷水与松手。 | 可设攀爬区、抓力、休息台和检查点；长按机关可设持续时间、松手衰减、完成后事件。这里的数值与规则是本版可配置的参考实现。 |

第 2 章 `room_dw_cyber_intro_1` 是 640×480；第 4 章 `room_dw_church_shelfclimb1` 也为 640×480，而第 5 章 `room_dw_castle_church_climb` 为 3840×3840。房间坐标与视口分离，能处理固定镜头的小房间和跟随镜头的大房间。瓦片及角色实例图层沿用 V0.4 的地图资产，前景层可单独选。

本版提取了 1,119 个含匹配项的房间、16,451 条候选。提取以对象名和初始实例为索引，不是游戏运行时的完整碰撞：有无有效遮罩、实例创建时被改写的碰撞、剧情触发以及脚本绘制都可能改变画面。无可靠尺寸的候选在编辑器标「估」。表中未命中的房间仍可从 V0.4 目录导入布景。

`tools/official-hints.csx` 可重新生成候选：每章把 `SCENE_HINTS` 指向对应输出 JSON，然后用 UndertaleModCli 的 `load DATA_WIN -s tools/official-hints.csx`。交付工程没有反编译脚本；运行时无需 UTMT 或 Steam 进程。
