# V0.5 场景与弹幕战斗整合规划

目标：用同一套工作台编辑场景与遭遇。对白或敌人接触可进入现有战斗，结算后在触发地点继续场景，并让不同结算走不同事件。保留 V0.5 旧场景格式和现有独立战斗工程；不改《大魔术秀》定稿。

| 顺序 | 实现 | 完成条件 |
|---|---|---|
| 1. 连接工程 | 场景里新增有稳定 ID 的战斗引用，关联已保存的遭遇文件或编辑器样例。提供战斗目录、绑定界面和打开对应遭遇编辑器的入口；统一启动器可管理战斗工作区。 | 在场景界面选择一场战斗、打开对应的原编辑器、保存后直接试玩。自制素材和被引用的弹幕仍由原有工具解析。 |
| 2. 触发与返回 | 事件指令可在任意对白、选项或演出后请求战斗；敌人物件支持接触和按键。战斗开始时冻结场景与输入，接入原战斗引擎和资源打包工具。 | 战斗期间不移动场景角色，不推进计时；战斗后保留房间、位置、镜头和场景进度。结算输入不串入下一段对白，重开及退出会释放战斗输入和音频。 |
| 3. 结算分支 | 用引擎实际结算事件连接胜利（击败敌人）、饶恕、队伍落败和逃离。每个引用可选四个剧情事件并写结果旗标；演出执行分支后续接原事件。 | 通过实际菜单走通四种结果；触碰一次只触发一次，离开再接触可重试；只在作者配置时隐藏敌人或跳去检查点。 |
| 4. 兼容与交付 | 同一套运行逻辑覆盖在线预览和离线 HTML，打包所用遭遇、弹幕、素材及战斗模块。提供示例、字段文档、引用诊断和可复放的验证。 | 断网打开导出的文件可完成整场战斗及返回分支；旧场景、独立战斗编辑和旧离线导出保持可用。 |

边界：场景进度由场景工程管理。每次战斗按遭遇文件配置开局，战斗 HP 和 TP 不默认跨场次继承。游戏本体和原版场景同步不作改动。
