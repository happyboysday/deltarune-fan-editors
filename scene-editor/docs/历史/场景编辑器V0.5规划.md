# DELTARUNE 场景编辑器 V0.5｜实现计划

目标：把 V0.4 的静态布景工作流扩展为能设计、试玩和独立分享的场景。官方房间、瓦片与角色作为制作资料；可玩的场景采用独立、可检验的数据格式。官方游戏目录、正常存档与 V0.4 发布包保持原样。

## 1. 官方证据与取舍

| 观察 | 本版对应能力 | 验收 |
|---|---|---|
| 第 2 章 `obj_mainchara` 分别处理移动/碰撞与跟随视口；门、NPC 和对白是独立对象/脚本 | 角色行走、碰撞块、互动范围与朝向、跟随镜头；门带条件和入口；分支对白、旗标与物品 | 从入口移动，不能穿墙；面对 NPC 对话后改变状态；门在解锁后正确换房间 |
| 第 3 章棋盘机关与节奏事件管理器按场景切换控制和判定 | 可复用的踩板/推块、惯性滑行；按拍输入事件，判定命中、失误和分支 | 通关可走成功分支，失败可重试；与对话、门和旗标联动 |
| 第 4 章攀爬有自己的输入、墙面与落点；第 5 章浇水按持续动作推进状态 | 场景内可切换走路、滑行、攀爬；消耗/回退检查点；长按互动、水壶式填充并解锁物件 | 模式切换不残留输入；松手中断可恢复；检查点复位和跨房间状态有效 |
| `scr_cutscene_commands` 将动作、等待、台词与镜头拼成序列 | 可复用的指令列表：显示/隐藏、旗标、物品、角色/镜头补间、对白、等待、转场、限时机关 | 演出锁定玩家，正常释放；不同事件可组合，不用在每个场景写代码 |

参考本机 Steam 数据（第 1–5 章）与 [DELTARUNE 官方画面](https://deltarune.com/)。解包产物仅用作本机调查；交付物不包含反编译脚本。官方房间的碰撞、门和机关数据只做可预览的候选提示，不凭物件名推断剧情或自动绑定传送目标。

## 2. 实施顺序

1. **可回收清理**：确认实际启用的战斗编辑器；旧安装包和明确属于制作的临时目录移到桌面回收站，保留定稿、源素材及最终交付，不再验证《大魔术秀》。
2. **保留旧工作流**：V0.5 独立目录和本机端口，复用 V0.4 的布景界面、房间/素材目录及 `director-map/1`。旧场景可导入作为布景；原有 GameMaker 同步仍由 V0.4 专用运行实例执行。新增互动使用浏览器试玩运行层，不依赖修改正版或运行任意 GML。
3. **场景运行**：使用 30 Hz 固定步长的场景状态机，分开布景、可玩角色、碰撞/机关、事件、进度和镜头。跨房间保留旗标/物品；不同试玩可独立重置；检查点用于回退；单份 JSON 可被界面和脚本共同验证。
4. **编辑与资料接入**：可导入 V0.4 房间、现有场景和 PNG，画布放置入口、墙、交互/触发区，常用类型可选模板；另提供精确 JSON 编辑、检验和帮助。通过只读房间目录加载官方尺寸、图层和候选位置。
5. **可分享与 AI 创作**：提供文件格式、有效示例与 CLI 校验/复放；导出时打包当前使用的图片和播放代码，离线 HTML 不依赖服务器。
6. **端到端验收**：完整试验工程走过对白分支、钥匙门、滑行推块、节奏、攀爬、长按机关和回到枢纽。对旧场景导入、编辑器保存/再打开、离线运行、非法引用诊断和固定步重放做验证。单独注明哪些机制是参考实现、哪些是真正从原版导入的数据。

本轮边界：覆盖可组合的场景玩法和关键互动范式；不逐个重制官方章节、剧情、小游戏素材或在正版程序内运行新工程。通过范例与扩展格式验收玩法而非逐场景宣称一致。
