# 场景编辑器 V1.0 开发者文档

## 架构与目录

服务端仅监听回环地址。Python 管理 HTTP、外部数据、设置、插件发现和本机游戏进程，Node.js 执行工程与插件校验、战斗打包和发布工具。浏览器用 ES 模块加载编辑器、预览和试玩。在线试玩与离线 HTML 复用同一世界模拟和插件接口。离线导出收集工程、素材、播放器及所选插件的静态依赖。

| 位置 | 职责 |
| --- | --- |
| `studio_server.py`、`studio_core/http.py` | 服务入口、路由、静态文件、Host／Origin／Fetch Metadata 检查、GET／HEAD／POST 及扩展路由 |
| `studio_core/a_assets.py`、`official.py`、`*_overlay.py` | A-export v8、官方房间、按需裁切 tile，以及原点、放置和可见性校正 |
| `studio_core/{user_assets,custom_assets,sequence_assets,registry_io}.py` | 自定义素材和序列登记、旧登记读取、并发锁和原子写入 |
| `studio_core/{settings,capabilities,layout}.py` | 设置解析、校验、备份和原子更新，逐功能能力报告，以及可选 V0.4 布景工作台 |
| `battle_host.py`、`chapter_host.py`、`chapter_navigation.py`、`chapter_window.py`、`ui_assets.py` | 战斗接线、正式章节生成与试玩、原生窗口和跑图、公共试玩资源 |
| `studio/` | 编辑器、设置页、插件管理与章节页。工程格式由 `format.mjs` 校验，规则推进在 `world.mjs`，绘制在 `view.mjs`，试玩和离线入口在 `player.mjs`、`standalone.mjs` |
| `studio/{plugin-manifest,plugins,plugin-bundle}.mjs`、`plugins_host.py`、`tools/plugin-files.mjs` | 插件清单、依赖排序、按工程注册、运行时错误隔离、模块打包、用户插件管理和 Node 端加载 |
| `studio/plugins/builtin/`、`examples/` | 地下城与赛车内置插件，场景示例、战斗定义和代码绘制的 `fireflies` 插件示例 |
| `tools/`、`docs/` | 工程与测试工具、发布脚本和技术参考。原规划与验收记录见历史目录 |

插件模式、实体和事件钩子连接到 `world.mjs`、`format.mjs` 和 `view.mjs`。编辑器挂载该工程声明的插件面板，内置模式也走同一注册表。图片由 `resources.mjs` 收集和预载，`bundleModules(project, read?)` 收集离线模块图，`makeHtml` 生成单 HTML 和 import map。插件清单、时序、钩子参数和示例以 [插件开发](插件开发.md) 为准。

## 接口一览

路径均在同一回环服务，POST 发送 `Content-Type: application/json` 并继承 HTTP 层的来源检查。HEAD 由分派层处理响应长度及正文。可用 `start(args, extra_routes=[provider])` 注册路由，或在监听前向 `server.extra_routes` 追加。提供者签名为 `provider(method, path, query, body, head_only)`，路径保留 URL 编码，查询值是字符串列表，读取请求的 body 是 `None`，POST 为解码后的 JSON。返回 `None` 继续分派，返回 `studio_core.http.Response` 则结束。

| 方法与路径 | 请求或用途 | 响应 |
| --- | --- | --- |
| GET `/api/a/rooms`、`/api/a/rooms/<room>` | 读取 A-export 房间目录、详情，查询参数 `chapter=chN` | 房间目录或房间 JSON。无可用数据时返回原因 |
| GET `/a-files/<root>/…`、`/official/…` | A-export 文件、官方素材和按需裁切资源 | 文件 |
| POST `/api/assets/resolve` | `{"chapter":"ch1","ids":[...]}` | 已解析素材列表 |
| GET／POST `/api/custom-assets` | 查询自定义素材或登记自定义 PNG | 列表或新登记 |
| GET `/api/animations`、POST `/api/animations/import` | 查询序列动画或导入动画帧 | 列表或导入结果 |
| GET `/custom-assets/<chapter>/<sha256>.png`、`/animation-assets/<chapter>/<sha256>.png` | 自定义素材／序列帧图片 | PNG |
| GET `/layout/` | 可选布景桥接 | 布景页面或配置说明 |
| GET `/api/studio/projects`、GET／POST `/api/studio/projects/<id>` | 工程列表、读取或按修订号保存 `{"project":{...},"revision":null}` | 工程和修订号 |
| GET `/api/studio/battles`、POST `/api/studio/battles/bundle`、`/api/studio/battles/edit` | 遭遇目录、打包校验、打开战斗编辑器 | 列表、资源或编辑器 URL |
| GET `/api/studio/settings` | 当前设置、来源及下次启动值 | `200`，含 `settings`、`data`、`boundPort`、`version`、`firstRunDone` 和 `warning` |
| POST `/api/studio/settings` | 如 `{"settings":{"assets":"D:/素材/场景编辑器素材","port":18947}}` | `200`，含整体 `ok`、每项 `results` 和新报告。CLI 项不可覆盖，有效项保存，路径变更显示 `pending` |
| GET `/api/studio/settings/detect` | 搜索相邻目录和当前路径 | `200`，`results` 含值、有效性和原因 |
| GET `/api/studio/capabilities` | 获取功能可用性 | `200`，`capabilities` 每项含 `label`、`available`、`reason`、`settings`、`missingSettings` |
| POST `/api/studio/restart` | `{}` | `202 {"ok":true,"exitCode":3}`，响应后退出，由启动脚本重启。有活动章节试玩时返回 409 及中文原因 |
| GET `/api/studio/plugins`、GET `/plugins/<id>/…` | 插件发现及已启用插件的静态文件 | 目录、清单、错误、启用状态、来源、工程列表或插件文件 |
| POST `/api/studio/plugins/install` | `{"folder":"D:/插件/fireflies"}` 或 `{"zip":"UEsDB..."}` | `201`，含 `ok`、`id`、`enabled`。冲突 `409`，校验失败 `422` |
| POST `/api/studio/plugins/<id>/enable`、`…/disable` | `{}` | `200`，含 `ok`、`id`、`enabled`。修改内置状态返回 `403` |
| POST `/api/studio/plugins/<id>/uninstall` | `{}` | `200`，含 `ok`、`id`、`trash` |
| POST `/api/studio/plugin-projects` | `{"tab":"标签页 UUID","project":{"id":"demo","title":"萤火小径","plugins":["fireflies"]}}`，关闭时传 `project:null` | `200 {"ok":true}` |

设置项可传 `null` 恢复默认路径，`firstRunDone` 与插件开关即时生效。损坏设置的备份位置通过设置与能力接口返回。插件静态路由对停用的插件返回 403。能力报告区分字体、UI 精灵、战斗、章节编辑、章节生成与章节试玩所需的资料。端点来源与验证记录见 [T1 原生服务端](历史/T1原生服务端验收.md)、[T2 插件运行时](历史/T2-插件运行时验收.md) 和 [T3 设置与插件管理](历史/T3设置与插件管理验收.md)。

## 外部数据与兼容

- 场景保存与章节保存分别按工程加跨进程锁。修订号冲突返回 409。章节编辑的修订号绑定来源，请把读取接口给出的值原样传回。章节工作区按来源目录、清单和初始编辑划分，有可核实构建记录的旧编辑会迁移。无法核实来源时，编辑接口的 `warning` 给出原文件和目标位置。
- 章节试玩从游戏安装目录取得运行程序和依赖，按 `dependencies.json` 核验。预构建需要匹配当前 `buildKey`，复制后的游戏数据需要匹配 `buildSHA256`。本机生成的 `build.json` 通过 `playGeneration` 指向完整发布的构建。每次启动都会组装独立的临时试玩目录。
- `/official/` 和 `/a-files/official/` 共用启动时通过校验的官方素材根。`/a-files/exports/` 使用通过校验的 A-export 根。这些路由只提供图片、JSON 和音频，响应带 CSP sandbox，页面禁止框架嵌入。
- 自定义 PNG 列表遇到损坏登记时，`issues` 逐条给出文件和原因。上传相同 PNG 会备份并修复对应的本机登记。
- 场景、布景、试玩档和插件使用各自的格式标识。编辑器发布号与 `deltarune-scene/1`、`director-map/1`、插件 API 1、设置版本 1 各自独立。工程省略 `plugins` 时启用两个内置插件，显式空数组使用基础玩法。 [场景工程接口](场景工程接口.md) · [第 5 章兼容字段](历史/第5章新增接口.md) · [宣传片场景接口](CH6-TRAILER-SCHEMA.md)
- 可直接读取 V0.4 的 A-export v8，独立资料可将 `v8/` 内容放入 `a-export/`。完整校正需要同级的 `metadata-overlays/`、`metadata-prototypes/`、`interface-review006.md`、`integration-admissions/review010-origin.json`。原版校正依赖的 `management/assets/official/` 可放在同级 `profile-official/`。仅有裸 v8 时，缺项通过 `source_import_profile` 标记。
- 新自定义素材写入数据目录 `user-assets/` 及 `user-assets/animations/`。旧 `legacy-user-assets/`、`legacy-animations/` 和 V0.4 的 `user-assets/` 继续只读回退，保留旧目录、URL 和现有项目引用。

## 测试

```powershell
node tools/test-all.mjs
node tools/test-all.mjs --browser
node tools/test-all.mjs --only test-release
node tools/test-all.mjs --list
```

快速层包含工程校验、模拟、HTTP 接口、状态回归、离线导出和解包启动验证。浏览器层由 `--browser` 启用，使用 Microsoft Edge 无头静音，可设置 `MSEDGE_PATH`。原生层在全测中记录跳过，按脚本参数单独运行，需要正版游戏、原生窗口或 UndertaleModCli。用 `--only` 按文件名片段筛选，可与 `--browser`、`--list` 合用。Python 解释器可用 `PYTHON` 指定。

测试素材优先级为命令行、环境变量、本机 `tools/test-env.local.json`、默认目录。命令行和环境变量相对路径从工作目录解析，JSON 相对路径从仓库根目录解析。填写本机绝对路径可避免目录歧义。素材位置的布局示例见 [V1.0 规划](历史/V1.0规划.md)。常用路径键如下。

| 命令行 | 环境变量 | JSON 键 |
| --- | --- | --- |
| `--assets` | `SCENE_ASSETS` | `assets` |
| `--battle-assets` | `DR_ASSETS` | `battleAssets` |
| `--official-root` | `DR_OFFICIAL_ROOT` | `officialRoot` |
| `--base` | `DR_V04_BASE` | `base` |
| `--a-export` | `DR_A_EXPORT` | `aExport` |
| `--ch6-assets` | `DR_CH6_ASSETS` | `ch6Assets` |
| `--battle-root` | `DR_BATTLE_ROOT` | `battleRoot` |
| `--projects` | `DR_PROJECTS` | `projects` |
| `--trailer-root` | `DR_TRAILER_ROOT` | `trailerRoot` |
| `--chapters` | `DR_CHAPTERS` | `chapters`，默认取 `assets/chapters` |

报告写入 `.codex-tmp/test-report.json`，包含结果和各项日志的位置。发现失败返回退出码 1。浏览器测试若显式传地址，应使用隔离的测试服务器，部分流程会保存或改动样例。 [V1.0 发布测试与历史基线](V1.0测试基线.md)

## 发布流程

1. 运行快速层与浏览器层，记录 PASS、FAIL、SKIP 和缺项原因。涉及 Windows 实际游戏的检查按需单独运行。
2. 在仓库根目录运行 `node tools/make-release.mjs`。默认输出到 `.codex-tmp/release/场景编辑器-V1.0.zip`，可在命令后传入自定义 ZIP 路径。需 Python 3.11 或更新版本。
3. 打包只收集程序、文档和示例。素材检查拒绝未经许可的图片、音频、字体和视频，列出命中文件。自带的示范精灵保存在 `studio/art/`，萤火示例用代码绘制。ZIP 内的 `release-manifest.json` 记录每个载荷文件的相对路径、字节数和 SHA-256。
4. 快速层的 `test-release.mjs` 会生成并解包 ZIP，校验清单，并从解压目录启动两次。仅字体、无素材环境均需通过首页、设置、插件管理的 HTTP 检查，验证能力报告和「萤火小径」模拟。
5. 以 [更新日志](../CHANGELOG.md) 和使用手册随 ZIP 交接。正式章节、官方素材及外部作品采用各自的目录配置。
