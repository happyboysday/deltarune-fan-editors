# 灵魂移动系统扩展规划

**本版范围：** 新玩法以独立机制接入。创作者可以分别选外观、移动方式和主动能力，给它们设参数，并在一段攻击中途切换。场地边界、敌弹裁剪、战斗结算仍沿用现有系统。冲刺射击和惯性赛车是两套验收样例。

## 现有接口要补的缺口

| 现状 | 对扩展的影响 |
| --- | --- |
| [模拟器](../engine/sim.js) 固定用方向和低速键换算红心位移；现有 `soul.mode` 不参与移动。旧 `soul` 事件只改颜色时还会回到战斗框中心。 | 要把换外观、换规则和传送分开，并保留旧事件行为。 |
| [遭遇战转接](../engine/encounter/world.js) 和 [独立攻击的离线自动演示](../tools/export-game.mjs) 在入模拟器前只转发方向和低速，现有 [演示输入编码](../engine/autoplay/soul.js) 也只认识固定动作。 | 冲刺和开火必须从键盘、自动演示、逐帧录像等入口完整传到同一处。 |
| [活动区求解器](../engine/arena.js) 已能处理移动、旋转战斗框和凹形场地，但只返回落点；现有敌弹命中主要检查每帧落点。 | 惯性需要墙面接触信息。高速移动和射击还要检查帧内走过的路径，不能只测起点或终点。 |
| [自动躲避](../engine/autoplay/bot.js) 和 [路径跟随](../engine/autoplay/follow.js) 按红心的固定速度估算下一步。 | 新机制要能重放真实输入；自动规划要么使用同一移动规则，要么明确提示暂不支持。 |

## 作品怎么设置

一套灵魂配置包含一份外观、一种移动方式、零到多项主动能力。外观包括颜色、贴图、锚点和是否随朝向旋转；移动规则控制速度与转向；主动能力可以请求冲刺位移或发射玩家弹。颜色不触发任何规则，同一种移动方式可以搭配任意外观，切回红色也不会自动卸下能力。

在攻击检查器里选初始配置；时间轴新增「切换灵魂配置」和「调整灵魂外观」事件。默认切换时保留位置和朝向，移动方式没变就保留其状态，变了就用新规则初始化速度；未换掉的能力保留状态，卸下的能力清空状态和冷却。传送需要显式填写坐标，由活动区校正，不把跳过的距离算进命中或擦弹。回合重开、跨攻击时从该段配置重新初始化，不隐式继承速度、子弹或冷却。

以下是作品格式片段：

```json
{
  "soul": { "profile": "pulse" },
  "soulProfiles": {
    "pulse": {
      "appearance": { "color": "#ffce45" },
      "movement": { "id": "free", "version": 1, "params": { "speed": 4, "slowSpeed": 2 } },
      "abilities": [
        { "id": "dash", "version": 1, "params": { "speed": 11, "durationFrames": 6 } },
        { "id": "shoot", "version": 1, "params": { "cooldownFrames": 8 } }
      ]
    }
  }
}
```

预设可直接从检查器选用，参数表由机制声明生成，包含名称、默认值、单位和范围。编辑器能预览并测试输入，显示当前速度、朝向、实际判定点与技能冷却。作品只保存配置、机制 ID 和版本。改配色或数值无需写代码；新增代码机制需在编辑器源码的注册表接入。首版用静态注册，由同一处提供参数定义、运行实现和所需素材；不从导入作品或网络地址加载脚本。编辑器可打开缺失机制的作品并保留配置，试玩和导出应明确报出缺失的 ID、版本与所在攻击，避免悄悄按红心运行。

## 机制接口

| 接口 | 机制能做什么 | 引擎负责什么 |
| --- | --- | --- |
| 逐帧输入 | 读取方向、低速、`dash`、`shoot` 等语义动作，以及按住和本帧按下的区别。机制可声明所需动作与默认按键。 | 键盘、编辑器、遭遇、离线页和回放共用输入格式。按下事件只消费一次，长按重复不触发冲刺；菜单和躲避分开，进入躲避时不重用确认键的旧按下事件。 |
| 移动规则 | `init` 建立状态；`step` 根据输入和上一帧状态计算期望位移；解算后可根据墙面接触更新速度或朝向。 | 固定以 30 帧每秒推进，解算实际路径和接触面。战斗框、全舞台、凹多边形走同一边界入口；机制不直接改世界坐标。 |
| 主动能力 | 按输入更新自己的冷却；冲刺可在本帧请求覆盖普通位移，射击可从移动后的玩家位置请求发射。 | 一帧最多接受一个位移覆盖；首版拒绝同时启用两项会争用位移的能力。命令由引擎统一执行，能力不直接修改敌弹列表或队伍 HP。 |
| 保存与回放 | 状态可序列化，例如车速、朝向、冲刺剩余帧和冷却；机制只读当前帧环境，需要随机数时使用引擎提供的有种子随机流。 | 快照保存机制版本、状态、玩家弹和随机状态。倒回、重开、快进和离线播放复用同一模拟逻辑，不以浏览器时间或渲染帧数推进。 |

首版把接口收在四个调用点：移动规则计算意图、移动规则接收墙面结果、能力在移动前申请位移覆盖、能力在移动后提交发射。场地结果包含实际走过的路径段和墙面法线。规则收到的是当前帧的只读信息与自己的状态，写回的是新状态和意图。冲刺和赛车通过这套接口表达；主循环不判断「现在是哪种心」。

每帧顺序：**应用时间轴事件和场地变化 → 读取动作 → 算出期望移动和实际路径 → 执行发射 → 推进弹幕并结算清弹 → 命中与擦弹 → 渲染**。赛车接触墙时只消掉朝墙的速度分量；冲刺撞墙时结束本次冲刺。高速命中沿实际路径检查，包括贴墙滑动的路径段；传送、换配置和普通移动要有明确标记，回放器不再靠「这一帧走太远」猜测是否传送。

玩家弹与敌弹按阵营区分，只有明确标为「可被玩家弹击破」的敌弹才能被打掉；旧弹幕默认不可破坏。玩家弹默认命中第一个有效目标后消失；沿路径先后判定，同一位置用稳定编号决胜。裁剪沿用原弹幕区域，在接触位置检查双方是否允许碰撞。首版约定同一模拟帧内先处理清弹，被击破的敌弹不再伤害玩家或发放擦弹 TP。玩家弹只清弹，不扣敌方 HP；冲刺默认不无敌。新机制路径使用高速判定，旧作品保留现有逐帧规则。

## 实施和验收

| 顺序 | 实施内容 | 验收标准 |
| --- | --- | --- |
| 1. 兼容底座 | 合并输入转接，将现有红心移动提成默认规则；旧 `soul` 字段、事件和旧输入编码通过兼容入口继续使用。 | 旧红心普通/低速、斜向、旋转框、全舞台和异形场地表现不变；《百变木偶》和《战斗区域试验场》仍走完原演示，旧作品 JSON 无需重存。 |
| 2. 接通配置和交付 | 接入注册表、参数面板、时间轴切换、快照，以及能记录新动作的版本化输入格式。新回放记录每帧的按住状态与一次性动作；保留旧格式解码，先保证实际操作可录可重放。 | 同一输入和种子在编辑器、遭遇和离线 HTML 中得到相同关键帧位置、技能事件和战斗结果；冲刺或惯性中途保存再恢复，后续结果与连续运行一致。用一个仅左右移动的测试机制验证注册表，不改场地、遭遇和导出代码也能接入。 |
| 3. 冲刺和射击样例 | 普通移动配合冲刺与射击；样例中途换色并启用能力，混排可破坏和不可破坏弹，射击方向沿最近一次有效朝向。 | 换色不跳位置；冲刺撞墙停止，穿越弹幕路径时仍可能受伤；按住冲刺不会连发；射击只清可破坏弹，裁剪区外的弹不会隔空被打掉。 |
| 4. 惯性赛车样例 | 增加油门、转向、制动、松手滑行和随朝向旋转的车体。首版使用现有圆形判定，预览可显示它与车体的关系。 | 对比起步、松油门、刹车、撞墙；高速进入异形场地凹角不穿墙，滑行时能重放和恢复快照。两套样例都交付可编辑工程、离线 HTML 和 MP4。 |

### 使用和扩展

- 在攻击检查器打开「灵魂配置」，从「新增预设」选择普通红心、冲刺射击或惯性赛车，再选择初始配置。时间轴用「切换灵魂配置」「调整灵魂外观」「传送灵魂」三个独立事件。按 V 冲刺、按住 B 射击；赛车用 ↑ 加速、↓ 或低速键制动、← → 转向。
- 将目标敌弹的「可被玩家弹击破」打开，才能用玩家弹清除。开启判定显示可以查看真实的红心圆、朝向、每帧速度和技能冷却。
- 按「录制」操作一段攻击，停止后工程保存输入轨迹。播放时选输入回放。旧的路径与录制字符串仍可用；新动作记录为 **v2:** 加输入段列表，每段含起始帧、按住动作、本帧按下动作和可选的方向覆写。
- 开发新机制时，把定义从 **engine/soul-mechanics.js** 的静态模块图接入，声明 ID、版本、界面名称、数值参数表及所用按键。移动规则实现 **init** 和 **step**，可选 **onResolved**；能力实现 **init** 和所需的 **beforeMove**、**afterMove**。参数和状态由引擎按配置传入，返回新状态和位移或发射意图。贴图素材由作品的外观配置引用。
- 样例 **soul-pulse** 和 **soul-racer** 可单独编辑；**soul-cockpit** 是将两段串联并提供操作说明的遭遇。旧作品可继续使用经典红心，无需添加配置。

首版保留旧红心的路径生成和避弹策略。新机制先用**输入录制回放**制作可靠演示；路径生成器和通用避弹机器人遇到未支持的机制要提示原因，不应按红心速度偷偷生成一条路径。后续有需要再用同一个移动步进做策略预测，把「能真实跑起来」和「机器人会玩」分开交付。首版不引入实体赛车物理、换大判定形状或通用视觉脚本系统。
